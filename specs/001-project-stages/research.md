# Research: «План» и индивидуальные «Варианты»

Дата: 2026-10-12. Новый объём: обновлённые FR-001–004/012–028/032, FR-040–041 и SC-019–020. Исследование исходников, без запуска приложения или тестов. Прежний дизайн удаления сохранён в [истории](history/project-deletion/research.md). Неизвестных проектных решений не осталось.

## R1. Две страницы без изменения wire enum

**Decision**: UI имеет PlanPage = plan | variants. Существующий `workflow.requestedStage` остаётся совместимым: object → plan; tile/rules/variants → variants. Новые сохранения нормализуют его в object/variants. Навигация доступна независимо от готовности; только подбор зависит от проверок. Нет отдельного router/backend endpoint.

**Rationale**: GraphWorkflow.tsx сейчас вычисляет четыре stage и блокирует переходы; schema.ts:488 уже читает все старые значения. project-lifecycle.ts возвращает на object/rules из-за отсутствия подтверждения/результатов — эти ограничения надо убрать для импорта/Undo.

**Alternatives considered**: новая версия документа и массовое переименование wire-полей избыточны; сохранение четырёх этапов отвергнуто пользователем.

## R2. Готовность и актуальность

**Decision**: использовать актуальный FaceCandidate из validate/command для текущего графа. Готовность требует attached room, valid face, совпадения accepted graph/draftRevision, отсутствия влияющего pending и валидных material/rules. acknowledged/confirmed не участвуют. request() строит полигон из текущего face; успешная проверка не создаёт фиктивного пользовательского acknowledgment. Смена только страницы не меняет актуальность готового результата и generation запроса; текущие optimize/layout завершаются в фоне с сохранением результата/ошибки без принудительной навигации.

**Rationale**: rooms.ts ready() и GraphWorkflow request()/currentKey привязаны к confirmed. FaceCandidate уже содержит polygon, validation, dependencyKey, geometryKey и measurementKey. API геометрии и расчёта менять не требуется.

**Alternatives considered**: автоматически проставлять флажки согласия семантически неверно; рассчитывать исторический confirmed скрыто вместо черновика запрещено.

## R3. Возвращение помещения

**Decision**: RoomRecord получает необязательную boundaryMemory с двумя SHA-256 ключами внешней границы. Сначала взаимно-однозначное совпадение для attached записей по full topology/outer topology, затем для остальных по retained topology/outer topology, затем точной внешней геометрии. Правила и ограничения подробно в модели. Отверстия исключены из идентичности, но включены в ключ расчёта. При неоднозначности — новые записи, старые detached, без случайного переноса настроек.

**Rationale**: независимое исследование подтвердило: rooms.ts:22 игнорирует detached при сопоставлении; backend/geometry/faces.py строит полный topologyKey по цепям и отверстиям. topology.py создаёт новые цепи при connect, deletion.py переназначает цепи после удаления сегмента. Поэтому прежнего topologyKey недостаточно для повторно нарисованной стены.

**Alternatives considered**: сопоставление по площади, пересечению, близости или порядку рисует ложную идентичность. История всех границ не требуется — сохраняется последняя прикреплённая граница. Точные канонические координаты позволяют восстановить то же помещение после пересоздания стены, без допуска/округления.

## R4. Старые документы, снимки и удаления

**Decision**: сохранить schemaVersion/file version 3, существующий каталог, CAS/Web Lock, deleteProject guards. Дополнительное поле принимает новый parser; отсутствие — null. Старые приложения не обязаны читать расширенный файл. Старые confirmed/acknowledgment/restorePoint сохраняются как исторические данные, не обновляются автоматически при validate и не определяют готовность. Существующее явное восстановление переименовать в «Вернуть план к сохранённому снимку»; без снимка действие не показывать. Очистка удаляет memory вместе с rooms, Undo восстанавливает; explicit deleteRoom удаляет целевую запись, временное размыкание её не удаляет.

**Rationale**: schema.ts проверяет точный набор ключей, потому изменение нужно провести через schema/types/storage/import, а не только React. Исторические снимки нужны для совместимости и не должны подменять текущие данные.

**Alternatives considered**: версия 4 и отдельный storage key создают лишние миграционные гонки; удаление старых snapshot-полей теряет пользовательские данные.

## R5. Имена и подписи

**Decision**: сохранять существующие непустые имена; новые автоматически получают «Помещение N» (следующий номер больше найденных числовых суффиксов и без конфликта имён, включая detached). Переименование: trim, 1–120 символов, одинаковые имена разрешены — выбор по ID. Визуальное имя и доступное имя области совпадают. Меню редактирует имя на «Плане» и выбранное помещение на «Вариантах». Подпись есть только у обнаруженной замкнутой области; исключённая область не комната.

**Rationale**: RoomRecord уже имеет name, а ProjectCanvas.tsx подписывает доступные области по индексу faces и не выводит сохранённое имя. Ограничение 120 символов уже задано parser.

**Alternatives considered**: обязательное окно ввода отвергнуто. Нумерация по индексу faces меняет названия при перестроении плана.

## R6. Размещение надписей и единицы

**Decision**: для подписи комнаты выбрать внутреннюю точку outer-minus-holes: горизонтальные сечения между соседними различными Y вершин, пересечения рёбер по even-odd, наиболее широкий допустимый интервал; фиксированный tie-break по Y/X. Это исключает центроид вне вогнутой области или в отверстии. SVG-текст не перехватывает клики, имеет постоянный экранный размер. Длинное имя визуально ограничивается доступной шириной с многоточием, полное остаётся в title/aria и меню.

Единый formatPlanLength: порог по исходным мм, >=1000 → м до четырёх десятичных знаков, иначе мм до одного; запятая и удаление хвостовых нулей. Использовать для DimensionOverlay и шага сетки. Координаты указателя тоже форматировать по каждой оси с единицей; знак сохраняется, порог для координат по модулю. NumberField и файл/расчёт/экспорт сохраняют мм; углы остаются градусами. Не менять формат ширин деталей в ведомости/меню результатов: это не линейная подпись плана.

**Alternatives considered**: округлять все метры до сотых теряет видимую точность 0,1 мм; вычислять геометрию по подписи недопустимо. Новый пакет для размещения текста не нужен.

## R7. Проверки

**Decision**: короткие Chromium e2e, один worker, 15 с тест/5 с действие, реальный backend на малых fixtures. Новый префикс `room flow ` во всех целевых тестах; сценарии F01–F12 в quickstart. Старые помощники confirmRoom/toRules адаптировать к автоматической проверке и двум страницам. Исторические проверки отдельных подтверждений заменить актуальными, а не симулировать скрытые кнопки.

**Alternatives considered**: нагрузочные, benchmark, pytest и отдельные unit/property/contract suites запрещены. Прошлые успешные тесты удаления не являются приёмкой нового сценария.


## R8. Фоновое завершение и первый рабочий инкремент

**Decision**: owner — общий GraphWorkflow, а page только представление. В navigate убрать resultGeneration++/setLoading(false) при смене только страницы; убрать автоматический возврат в старый этап и navigate из optimize success. Live guard одинаков для optimize/layout: alive, epoch, request generation, projectId, roomId, текущий fingerprint и актуальная проверка графа. Не сравнивать page/documentRevision/localRevision как причины устаревания: метаданные и autosave страницы их меняют без изменения расчёта.

**Rationale**: независимое read-only исследование подтвердило конкретные старые пути: GraphWorkflow.tsx:197–216 отменяет ожидание и перенаправляет, :392 открывает variants после ответа, :158–165/:351–360/:524–545 зависят от confirmed. rooms.ts:47–52 также возвращает object при утрате комнаты; useGraphProject.ts:191–224 фабрикует legacy acknowledgment. Эти переходы нужно убрать/перевести на актуальный face уже в US1, включая проверку экспорта. Нельзя объявлять MVP с автоматической готовностью, оставляя старый confirmed в ключе результата до US5.

**Alternatives considered**: отменять запрос при смене страницы противоречит принятому уточнению; принимать любой поздний ответ нарушает защиту изменённого выбора. Перенос состояния в размонтируемую страницу теряет фоновые операции. Полная документная ревизия в токене излишне отменяет запрос при неизменных входных данных.

**Validation**: F09 отдельно для optimize/layout success/error и готового результата, без sleeps; смена комнаты/входных данных остаётся контрольным отказом. F12 явно проверяет альтернативы, метрики, деталь, сдвиг, закрепление и экспорт. Тесты/сборка при планировании не запускались.
