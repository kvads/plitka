# Project file contract: flow и память помещения

Дата: 2026-10-12. Расширяет v3 без нового envelope/endpoint. Неизменённые поля, строгие ссылки, лимиты графа, clear/Undo и миграция v1/v2 описаны в [предыдущем контракте](../history/project-deletion/contracts/project-file.md); текущие правила readiness и страниц имеют приоритет над прежними подтверждениями.

## Формат

Файл ≤2 МиБ, schemaVersion=3. Сохраняются идентичность/адрес проекта, граф и условия, pendingEdit, старый restorePoint, комнаты, индивидуальные material/rules/fieldInputs, selectedRoomId, workflow и viewport. Результаты и runtime readiness не сериализуются.

В RoomRecord добавляется optional `boundaryMemory: null | {topologyKey:string, geometryKey:string}`. Оба ключа — 64 строчных шестнадцатеричных символа SHA-256; лишние поля memory отклоняются. Отсутствие поля в старом документе допустимо и нормализуется в null. Подписи вычисляются только из внешней границы согласно [модели](../data-model.md) и [исследованию](../research.md), без округления мм. Отверстия не входят в identity memory, но участвуют в calculation dependencies.

Читатель принимает прежние object/tile/rules/variants. Отображение: object → plan, остальные → variants; следующая запись использует object/variants. Отсутствие результата/selectedRoomId и pending не принуждают к другой странице. Старые acknowledgment/confirmed/restorePoint читаются совместимо, но не разрешают и не запрещают расчёт. Успешная валидация не создаёт acknowledgment.

Существующие непустые имена сохраняются; пустым старым именам назначается свободное «Помещение N» при нормализации. Новое переименование: trim, 1–120 символов. Дубликаты имён допустимы, связь по ID. Счётчик учитывает detached комнаты и не переименовывает оставшиеся.

## Нормализация и запись

Attached записи получают memory из актуального сопоставленного face. Detached запись может получить seed из старого confirmed только при совпадении topologyKey записи и снимка; иначе memory остаётся null и доступно только точное legacy topology matching. Не следует угадывать историю по близкой геометрии. Повторная нормализация идемпотентна; физическая геометрия не ремонтируется.

Нормализованный документ сохраняется обычным autosave только при реальном изменении, под прежним CAS/Web Lock. Чтение повреждённого каталога или некорректного файла не записывает частичный документ и не заменяет рабочий проект. Импорт проверяет весь файл до commit; изменения localRevision за время чтения требуют существующего разрешения конфликта, не молчаливого overwrite. Импорт из списка создаёт новый UUID.

## Жизненный цикл

При временном исчезновении face RoomRecord становится detached с прежними именем, настройками и memory. Восстановление взаимно однозначного внешнего контура возвращает его ID; алгоритм разрешения неоднозначности обязателен и описан в модели. latest attached memory обновляется только после принятия актуального face. Явное удаление помещения удаляет его RoomRecord и memory; clear удаляет все комнаты, а Undo возвращает полный предшествующий документ.

Хранение по ключу `plitka-projects-v3`, документные ревизии, отказ stale-save, пустой каталог после последнего удаления и запрет resurrection остаются по [контракту удаления проектов](project-deletion.md). Новый читатель принимает старые v3; старый клиент не обязан принимать расширенные файлы. Неактивные v1/v2 backup keys не изменяются и не восстанавливаются автоматически поверх существующего v3.


Нормализация старых пустых имён выполняется общим normalizer при чтении/миграции до приёмки совместимости US1; автоимя новой комнаты использует то же правило в US2. Фоновое состояние запроса, loading/error и accepted/pending/locked остаются runtime и не входят в файл. Сохранение только страницы/метаданных меняет документную ревизию для CAS, но не вычислительные зависимости или поколение запроса.
