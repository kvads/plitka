# Contract: окончательное удаление проекта

FR-039, SC-018, US1.13–16. Это локальный контракт хранения и UI, не HTTP API. Геометрические endpoints не меняются.

## deleteV3(projectId, expectedRevision)

Размещение: `frontend/src/domain/plan/storage.ts`. Аргументы: непустой ID и неотрицательная целая сохранённая ревизия; expected=null запрещён. Результат — DeleteProjectOutcome из [модели](../data-model.md).

1. Получить существующий exclusive Web Lock `plitka-projects-write`. Без поддержки Locks — прежний явный отказ; обхода нет.
2. Перечитать и валидировать каталог v3 под lock. Повреждение не трактуется как пустой каталог.
3. Отсутствующий ID → alreadyMissing без setItem. Отличающаяся ревизия → conflict без setItem.
4. Сформировать каталог из свежих rows без выбранного ID. Одним setItem записать `{schemaVersion:3,projects:remaining}`; при [] ключ сохраняется. Остальные документы не редактировать, их ревизии не повышать.
5. Только после успешной записи вернуть deleted. Исключение не скрывать, success не публиковать. Нет server request, pending graph-команды или записи Undo удаления.

Повторное подтверждение блокируется во время deleting. API saveV3 сохраняет прежние overloads и predicate; для числовой expected отсутствие документа остаётся отказом, ни один retry не меняет её на null.

## Подтверждение из редактора

Открытие диалога не изменяет документ и не отключает обычное сохранение. Захватить ID, сохранённую expectedRevision и localRevision; данные подтверждения должны явно идентифицировать проект. Если localRevision изменилась до клика подтверждения, не отправлять удаление, запросить новое подтверждение. Если успело сохранение или другая вкладка изменила сохранённую ревизию, deleteV3 возвращает conflict; не подменять expected автоматически.

Перед вызовом на подтверждении: поставить deleting guard, повысить lifecycle/write epochs, запретить новые команды/сохранения. Не очищать исходный документ до успеха. Старые queued snapshots проверяют guard до lock и внутри lock; уже записавшаяся старая ревизия не публикует payload и проверяется через CAS удаления. На успехе очистить runtime и сообщить владельцу; после ошибки оставить doc/history/pending и вернуть доступ к работе/повтору по текущим правилам conflict. Старые ответы и очередь не возобновляются; новые актуальные записи используют новую эпоху. Обычный unmount без удаления продолжает сохранять последний актуальный snapshot.

Все async пути сохраняют guard success/error/finally: validate, graph command, legacy retry, deletion-preview объектов плана, optimize, layout и importV3/File.text. Успех удаления не должен ждать их ответов. JSON/SVG/CSV не имеют новых endpoints; после удаления редактора экспорт старого runtime недоступен.

## Вкладки и маршруты

Projects слушает storage для KEY и перечитывает актуальные rows. Отсутствие активного ID закрывает редактор, инвалидирует его runtime и возвращает список с сообщением. Существующий ID с новой ревизией вызывает прежний конфликт, без автоматической потери черновика. Hook отдельно обрабатывает исчезновение: `if (d && revision differs)` недостаточно.

Локальный deleted/alreadyMissing явно обновляет rows и маршрут; storage event в этой вкладке не ожидается. Результат старого onSaved не добавляет отсутствующий ID. Ссылка `#project/<deleted-id>` показывает «Проект не найден» и действие «К списку проектов», без создания пустого документа.

## Диалог и пользовательские действия

Кнопка «Удалить проект» у каждой строки списка и в ProjectMenu; «Очистить проект» сохраняет существующее поведение. Один общий DeleteProjectDialog, название и адрес при наличии, пояснение полного удаления без отмены, кнопки «Отмена» и «Удалить проект». Фокус сначала на отмену. До отправки Escape/закрытие равнозначны отмене; после отправки показывается занятость и исключаются повторная отправка/закрытие, выдающее обещание отмены уже выполняемого удаления. При ошибке диалог позволяет повторить или закрыть. При конфликте показать актуальные данные и требовать отдельного нового подтверждения.

Диалог modal с focus trap и недоступным фоном; форма не вызывает команды полотна. После отмены фокус возвращается инициатору, после удаления — заголовку списка; fallback списка не зависит от SVG. На 375/1440 px нет горизонтальной прокрутки. Уже удалённый ID — сообщение «Проект уже удалён» и обновлённый список. Последний удалённый проект — пустой список с «Новый проект». Идентификация всегда по ID, даже при одинаковых названиях.

## Совместимость

Существующий пустой v3 предотвращает initializeV3 миграцию старых каталогов; removeItem(KEY) запрещён. По FR-039 и уточнению A1 полное удаление охватывает активный документ и состояние редактора. Старые резервные ключи сохраняются без изменений, не являются активным документом или корзиной и не подключаются автоматически. Явный импорт скачанной копии из списка сохраняет создание нового UUID; импорт в удалённый/закрытый редактор отвергается guard. Контракт не обещает работу устаревшей версии приложения, обходящей текущие правила записи, или восстановление после ручного удаления системных ключей браузера.
