# UI contract: «План» и «Варианты»

Дата: 2026-10-12. Этот контракт заменяет прежний flow этапов и подтверждения готовности. Остальные действия редактора сохраняются по [историческому контракту](../history/project-deletion/contracts/workflow-ui.md), включая инструменты, безопасность вершин, удаление и угол. При расхождении новый контракт приоритетен только для описанного здесь объёма.

## Навигация и готовность

Всегда доступны две страницы «План» и «Варианты» на общем полотне. Новому проекту открывается «План». Старый object соответствует «Плану», tile/rules/variants — «Вариантам». Нет плитки/правил как отдельных этапов. Отсутствие комнаты, результата или валидной геометрии не запрещает переход на страницу и не перенаправляет пользователя.

На «Плане» доступны инструменты геометрии и контекст объекта. На «Вариантах» пользователь явно выбирает замкнутое помещение по имени, видит его выделение и индивидуальные плитку/правила, запускает подбор. Выбор доступен клавиатурой и различает комнаты по ID даже при одинаковых именах. Нет неинформативных списков стен/вершин. При отсутствии подходящих комнат показывается причина и действие перехода на «План».

Нет «Подтверждаю показанные размеры», «Подтвердить помещение» или эквивалентного обязательного шага. Для подбора нужны текущая валидная область, accepted revision текущего графа, отсутствие влияющего pending и валидные настройки выбранного помещения. Ошибки других независимых областей не блокируют валидную выбранную комнату. Во время проверки расчёт недоступен с понятной причиной. Правила смещения проверяются при явном запуске. Ошибки остаются на «Вариантах» и не уничтожают введённые поля.

## Имена

Каждая распознанная замкнутая область, не являющаяся отверстием, получает «Помещение N» и подпись на полотне. Нумерация и восстановление определены в [модели](../data-model.md). На обеих страницах показываются имена текущих замкнутых комнат. Незамкнутые области, detached записи и исключённые области не подписываются как помещения.

Переименование доступно из меню помещения (не стены/вершины); обязательного модального окна нет. Пробелы по краям удаляются, пустое имя и длина более 120 символов отклоняются без потери прежнего имени. Изменение сохраняется автоматически, не инвалидирует расчёт.

Подпись располагается внутри области вне отверстий по алгоритму R6 исследования; не перехватывает клики полотна. Длинное имя сокращается визуально, полное доступно через title/accessible label. На 375/1440 px и при zoom подписи/меню остаются читаемыми и не создают горизонтальный скролл страницы.

Размыкание скрывает подпись, прекращает подбор этой комнаты и инвалидирует её результаты. Однозначное восстановление возвращает имя/настройки, но не старые результаты. Неоднозначные split/merge создают новые записи; старые detached записи не предлагаются как пригодные комнаты.

## Результаты и асинхронность

Запрос использует polygon текущего face в мм; confirmed snapshot не является fallback. Изменения зависимостей комнаты, условий размеров, материала или правил инвалидируют результат, даже если координаты прежние. Переименование, адрес, zoom/resize не инвалидируют его. После исчезновения/изменения комнаты старый результат не оживает при возвращении прежнего fingerprint.

При переключении комнаты нельзя показать или экспортировать результаты другой комнаты. Любой ответ сверяется с project/room/fingerprint/generation и lifecycle epoch; закрытие, импорт, очистка и удаление отсекают старые success/error/finally. Отсутствие результата после reload — обычное пустое состояние страницы, подбор запускается явно. Смена только страницы не инвалидирует готовый результат и не отменяет текущий optimize/layout: актуальные success/error/finally сохраняются в фоне без навигации, при возвращении отображаются результат, ожидание или ошибка с повтором. Экспорт готового актуального результата после возвращения доступен без нового запроса.

## Единицы

Для подписей длин стен, размерных диапазонов и шага сетки: значение от 1000 мм отображается в м с максимум четырьмя знаками; ниже — в мм с максимум одним. Десятичный разделитель — запятая, конечные нули убираются. Порог проверяется до округления: 999,9 мм; 1000 → 1 м; 3175 → 3,175 м; 3175,5 → 3,1755 м. Если полотно показывает координату указателя, правило применяется по абсолютному значению каждой оси с сохранением знака. Углы остаются в градусах. Поля ввода, файл, API и экспорт ведомости остаются в мм, formatter не меняет модель.

## Разрушительные операции

Подтверждения удаления объектов/помещений, очистки и удаления проекта сохраняются. Удалённое меню закрывается сразу после успешной операции. Clear оставляет проект, сбрасывает на «План» и очищает комнаты/memory/результаты; его одношаговый Undo сохраняется. Удаление проекта окончательно по [контракту удаления](project-deletion.md). Старый restorePoint доступен только как «Вернуть план к сохранённому снимку», не как подтверждение готовности; новые автоматические restorePoint не требуются.


## Непрерывность страницы вариантов

Owner запроса живёт до закрытия/замены проекта, независимо от активной страницы. Переход на «План» не сбрасывает выбранную альтернативу/деталь, accepted placement, pending ручного сдвига, locked, loading и ошибку. На «Плане» результат не обязан отображаться; при возвращении состояние соответствует последнему актуальному ответу. Новые запросы не запускаются при переключении страницы. Error не делает ошибочный результат доступным для экспорта. Все изменения выбора комнаты/данных и разрушительные действия сохраняют прежние ограничения актуальности.

FR-022 проверяется отдельными короткими сценариями: сравнение как минимум двух полученных альтернатив и метрик; выбор детали; успешный ручной сдвиг; закрепление с недоступным изменением смещения до снятия; SVG/CSV из актуального accepted; ошибка ручного пересчёта с блокировкой экспорта. При переходе только между страницами эти действия и состояние не теряются.
