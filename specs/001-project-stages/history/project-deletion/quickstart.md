Дата: 2026-10-12. План проверки FR-039/SC-018, US1.13–16. **Реализация завершена 2026-10-12: 38 новых быстрых e2e и 7 адресных регрессий прошли; TypeScript/Vite build прошёл.** Предыдущие результаты T122–T176 сохранены в [истории](history/context-editor/quickstart.md); исторические 91 e2e также не являются результатом нового инкремента.

## Среда и запуск при реализации

Использовать существующую .venv и frontend/node_modules; зависимости не обновлять. В двух терминалах из корня проекта:

```bash
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
npm --prefix frontend run dev
```

Если серверы уже работают, использовать их без перезапуска. Все browser tests запускаются из `frontend/`:

```bash
npx playwright test tests/projects.spec.ts tests/project-document.spec.ts tests/project-stages.spec.ts --grep 'delete project ' --workers=1 --timeout=15000 --reporter=line
npm run build
```

Префикс `delete project ` обязателен для новых сценариев во всех трёх целевых файлах, включая D05/D06 в `project-document.spec.ts` (T181, уточнение C1). Сценарии реализованы в указанных файлах. Отсутствие найденных тестов не считается успешной приёмкой. Конфигурация уже задаёт Chromium, action timeout 5000 мс, test timeout 15000 мс и один worker. Запускать только адресные новые и реально затронутые регрессии. Build/typecheck разрешены при реализации.

**Запрещено** запускать performance/load/stress/benchmark, pytest, отдельные unit/property/contract-наборы и общие команды, косвенно вызывающие их. Не использовать пользовательский проект для проверки удаления. Никаких нагрузочных fixtures, замеров скорости или sleeps для гонок.

## Подготовка fixtures

Изолированный browser context; маленький v3 каталог с двумя разными ID и одинаковым названием, один полный проект с pending/restorePoint/settings, второй неизменный контрольный. Для вкладок две pages одного context, чтобы storage/Locks были настоящими. Старые migration keys используются только как тестовые данные. File.text и сетевые ответы задерживаются управляемыми promises, успех геометрии возвращается настоящим backend. Ошибка setItem моделируется адресно в изолированной вкладке. Пользовательские localStorage не читаются/не меняются.

## Сценарии

Каждая группа делится на короткие отдельные тесты; таблица не требует одного длинного end-to-end сценария. Ожидаемые поля/исходы определены в [контракте](contracts/project-deletion.md) и [модели](data-model.md).

| Группа | Действие | Ожидаемый результат |
| --- | --- | --- |
| D01 | Из списка открыть подтверждение, отменить кнопкой/Escape; отдельно подтвердить удаление одного из двух одноимённых проектов | При отмене каталог побайтно прежний. При успехе удалён только выбранный ID, имя/адрес показаны верно, остальные поля/ревизия второго проекта сохранены |
| D02 | Удалить из меню открытого проекта с планом, pending, настройками и restorePoint | После успешной записи список, нет редактора/старого Undo/результата. Clear проверяется отдельно: он оставляет запись. Не требуется решать геометрию перед удалением |
| D03 | Удалить последний проект, обновить страницу, открыть старый hash | Ключ v3 существует с projects:[], пустой список предлагает создание, старый URL даёт «Проект не найден» и переход к списку |
| D04 | Последний v3 имеет соответствующие старые v2/v1/legacy данные, затем удаление и reload | initializeV3 видит пустой v3 и не возвращает старый проект; резервные ключи не меняются |
| D05 | Отказ setItem, отсутствие Web Locks; отдельно повреждённый каталог | Нет ложного успеха, до успешной записи исходные данные сохранены, показана ошибка и доступен повтор. После снятия отказа новая явная попытка работает |
| D06 | Другая вкладка записала новую ревизию после диалога; отдельно save→delete, delete→save, уже отсутствующий ID | Конфликт требует нового подтверждения, новый документ не удалён молча. Поздний save не создаёт запись. alreadyMissing даёт сообщение и список. Изменение другого ID сохраняется |
| D07 | Удаление открытого проекта из другой вкладки; отдельно поздние validate/command/legacy/object deletion-preview/optimize/layout/File.text | Открытая копия закрыта, правки и запись прекращены, поздний success/error/finally не возвращает данные/меню/результат. Каждый путь и вид ответа — отдельный короткий сценарий |
| D08 | Скачать файл, удалить проект, явно импортировать файл из списка | Создан новый UUID, исходные данные из файла сохранены, старый ID остаётся отсутствующим. Повтор создания обычного нового проекта работает |
| D09 | Диалог на 375/1440 px, клавиатурное открытие, Tab/Shift+Tab/Escape и повторный клик подтверждения | Фокус сначала на отмене, фон недоступен, нет горизонтальной прокрутки; отмена возвращает кнопку, успех — заголовок списка; только одна операция |

D06 также проверяет изменение localRevision до подтверждения и собственное сохранение после открытия диалога: подтверждение устаревает, автоматической подстановки новой ревизии нет. Для ожидания Web Lock используется настоящий gate, освобождаемый сразу после нужного действия. Сравнивать данные и наличие записи, а не только текст уведомления.

D07 включает завершение уже ожидающей записи после unmount удаления и поздний onSaved: проект не появляется в каталоге/списке. Контрольная регрессия обычного выхода без удаления подтверждает, что последняя актуальная запись по-прежнему сохраняется. Сохранённый черновик после ошибки удаления остаётся доступен и не заменяется старым ответом.

## Регрессии и фиксация результата

После реализации адресно проверить создание проекта, изменение названия/адреса, импорт с новым UUID, обычный выход с автосохранением и очистку/Undo очистки. Геометрические алгоритмы не меняются; полный повтор старых наборов не нужен без обнаруженного влияния.

В итоговом реестре записать фактические команды, число прошедших/непрошедших тестов, исправления и адресные повторы; не складывать пересекающиеся запуски в число уникальных тестов. Проверка build не заменяет e2e.
