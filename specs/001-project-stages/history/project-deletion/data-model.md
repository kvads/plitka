# Data model: удаление проектов

Дата: 2026-10-12. Расширение FR-039/SC-018 поверх реализованного v3. [Предыдущая модель](history/context-editor/data-model.md) продолжает описывать геометрию, комнаты и очистку.

## ProjectCatalogV3 — существующий

`{schemaVersion:3, projects:ProjectDocumentV3[]}` в `plitka-projects-v3`. ID уникальны, названия могут совпадать. Удаление убирает ровно один ID, не меняет ревизии/поля остальных документов. Пустой массив допустим и обязательно сохраняется. Формат файла проекта и лимит 2 МиБ не меняются; backend и графовые команды не расширяются.

Старые резервные копии legacy/v2 не входят в активный ProjectCatalogV3: удаление их не изменяет. Они не служат корзиной и не подключаются автоматически, в том числе при пустом projects. Удаление активного документа и очистка runtime — границы полного удаления по FR-039 (A1); новой сущности хранения не требуется.

## DeleteProjectIntent — только runtime

| Поле | Правило |
| --- | --- |
| projectId | Существующий ID в момент открытия подтверждения |
| expectedRevision | Неотрицательное целое из сохранённого документа; null запрещён |
| name / address | Показанные пользователю метаданные подтверждаемой версии; в редакторе также видны текущие метаданные черновика, если они не сохранены |
| localRevision | Только для редактора: ревизия локального состояния в момент открытия |
| origin | list или editor, для маршрута и фокуса |
| requestId | Runtime идентификатор одной попытки; старый callback не меняет новый диалог |

Не хранит копию проекта, не сериализуется, не входит в Undo. Смена target/revision требует нового подтверждения.

## DeleteProjectOutcome — локальная операция

- `deleted {projectId, projects}` — setItem успешно завершён; projects — свежий оставшийся каталог.
- `alreadyMissing {projectId, projects}` — ID уже отсутствует; без записи и без повторного создания.
- `conflict {projectId, current, projects}` — ревизия отличается; без записи; current используется только для нового явного подтверждения, не для молчаливой подмены черновика.
- Исключение чтения/валидации/записи или недоступности Web Locks — success не возвращается, каталог не меняется.

## ProjectDeletionState — только runtime

`idle → confirming → deleting → deleted`; cancelling до отправки возвращает idle без изменения epochs/doc. Из deleting при ошибке → failed (doc/history/intent сохранены); при конфликте → conflict. Retry ошибки создаёт новую попытку; конфликт требует обновлённого подтверждения. alreadyMissing имеет тот же terminal эффект, что deleted, но отдельное сообщение.

У редактора действуют existing lifecycleEpoch/writeEpoch/localRevision плюс terminal missing/deleted и временный deleting guard. На начале подтверждённой попытки epochs возрастают, старые async callbacks становятся неактуальными. При ошибке epochs не уменьшаются. После deleted команды, persist и retry запрещены; новый экран не использует старую историю. При storage-событии с отсутствием ID переход прямо в deleted/missing.

## Сохранение и владение

Числовая expectedRevision обязательна для изменения существующего проекта, в том числе после unmount. expected=null разрешена только отдельным созданию/импорту с новым ID. Удаление и сохранение используют один lock; запись, успевшая до удаления, вызывает conflict; запись, пришедшая после удаления, не проходит CAS. Обновление списка не должно создавать строки из старого onSaved.

Скачанный файл не удаляется. Явный импорт из списка создаёт новый UUID и documentRevision=0. Точки/стены/условия внутри импортируемого проекта сохраняют допустимые ID своих снимков; они не являются глобальными ID проекта. Корзина, tombstone, удалённая ProjectDocumentV3 и undo-delete отсутствуют.
