# Implementation Plan: Защита вершин и диагностика нулевой стены

**Branch**: `001-project-stages` — идентификатор функции из setup-plan; Git-ветка не создавалась. **Date**: 2026-10-11. **Spec**: [spec.md](spec.md).

## Summary

Расширить работающий графовый редактор по FR-034 и SC-013: запретить создание совпадающих вершин всеми командами, показать защитные круги радиусом 12 CSS px в инструменте добавления и объяснять конкретную нулевую стену с обоими её концами. Радиус защищает указательный ввод после привязки; он не задаёт минимальное расстояние в миллиметрах для числового ввода.

Базовая реализация графа v3 завершена: T047–T097 остаются выполненными. Её план сохранён в [history/graph-v3/plan.md](history/graph-v3/plan.md). Настоящий план — следующий инкремент, а не повторная реализация редактора. Новые задачи T098–T121 добавлены в `tasks.md`; выполненные T047–T097 не переоткрываются.

Старые документы со совпадающими вершинами открываются с диагностикой, без объединения, удаления, округления или переписывания геометрии. Автоматическое исправление существующего пользовательского проекта не входит в согласованный объём.

## Technical Context

**Language/Version**: существующие Python 3.12–3.14, TypeScript 5.9, React 19.2.

**Primary Dependencies**: FastAPI, Pydantic, Shapely 2, NumPy, SciPy; Vite 7, SVG и Pointer Events. Новых зависимостей не требуется.

**Storage**: прежние ProjectDocumentV3 и JSON envelope v3, localStorage `plitka-projects-v3`, Web Lock `plitka-projects-write`. Без Web Locks существующая реализация отказывает в записи с сообщением. Backend stateless. Новый формат, миграция и серверное хранение не нужны.

**Testing**: только быстрые Chromium Playwright e2e на небольших фикстурах, плюс build/typecheck. Один worker, test timeout 15 с, action timeout 5 с. Performance, нагрузочные, стресс-тесты, benchmark, pytest и отдельные unit/property/contract-наборы не запускать, включая косвенный запуск. В фазе планирования проверки исполнения не запускаются.

**Target Platform / Project Type**: существующее веб-приложение React + FastAPI; мышь, touch/pen, клавиатура; узкое и широкое окно.

**Performance Goals**: локальная подсветка без сетевых запросов на pointermove. Новых количественных целей скорости нет; нагрузочная пригодность не проверяется.

**Constraints**: координаты в мм, размеры в мм/°, прежние лимиты и точность сохраняются. 12 CSS px измеряются после преобразования в экранную систему и после snapping. Точное равенство координат не зависит от zoom, сетки и допуска размерного решателя. EPS=1e-7 мм остаётся численным допуском вычисленной топологии и проверки вырожденных стен, а не физическим радиусом запрета независимых точек.

**Scale/Scope**: точечные изменения команд, независимой проверки решателя, полотна, сообщений и e2e. Четыре этапа, раскладчик и формат документа сохраняют прежние контракты. До 2100 вершин/6300 сегментов и цепей, 12600 условий, 20 voids, 2 МиБ на запрос/файл; предельные размеры не используются как тест нагрузки.

**Structure Decision**: расширять фактический `domain/plan`, сохраняя `domain/room` и `domain/project` для v2-совместимости. Сервер проверяет семантику любых команд; локальная проверка улучшает обратную связь, но не заменяет сервер. Круги, hover и диагностическое выделение — runtime, не поля JSON.

## Implementation sequence for task generation

1. Добавить общий анализ совпадающих координат и сравнение basis/candidate; расширить zero_wall концами, сохранить адресную область влияния. Диагностику и запрет новых дефектов не связывать с форматом чтения старых файлов.
2. Разделить явное создание точки и топологическое переиспользование при connect. Проверить addVertex, обе заготовки, move и все размерные команды; атомарно отвергать новый дефект во всём графе, включая другие компоненты. Нормализация решателя не должна менять незатронутые вершины.
3. Встроить в полотно круги 12 CSS px и проверку итогового snap на preview/commit; числовой ввод проверять только на совпадение координат. Блокировка указательного добавления не создаёт pending или Undo.
4. Ввести отдельное выделение диагностики: нулевая стена, два конца, координаты и понятные обозначения; не выбирать здоровую вершину как объект удаления. Сгруппировать каскадные сообщения одной причины, сохранив независимые ошибки. Для разных координат концов при длине ниже EPS сообщать о слишком малой длине, а не о совпадении; сверять точные значения, не отображаемое округление.
5. Добавить малые e2e G15–G22 с реальным FastAPI и изолированными документами: G18a проверяет добавление в US2/T113, G18b — перемещение после изменений solver в US3/T118; G21 отдельно проверяет разные координаты при длине ниже EPS. Проверить затронутые прежние сценарии, выполнить build/typecheck. Обновить фактическую запись проверок только после исполнения.
