# Research: этапы проекта и редактор помещения

Дата: 2026-10-11. Основание: spec.md, исходные четыре ответа Clarifications и последующее указание применить рекомендации анализа, чтение действующего приложения и два независимых исследования геометрии и сохранения. Это решения для будущей реализации; приложение и зависимости в этой фазе не изменялись, тесты не запускались.

## 1. Границы редактора и расчёта

**Decision:** Выделить домен помещения: контуры, размерные условия, черновик, подтверждение и диагностика. Сохранить существующие `/api/layout`, `/api/optimize` и геометрию `backend/planner.py`. Добавить отдельные операции проверки и согласования геометрии. Адаптер передаёт раскладчику только проверенные координаты в мм и параметры плитки/правил.

До явного подбора rulesReady проверяет только числовые поля; область после отступа проверяется существующим optimize/layout при запуске. Ошибка оставляет пользователя на текущем этапе с сохранёнными значениями.

**Rationale:** Сейчас `Project` смешивает геометрию, параметры плитки и смещение сетки; `App.tsx` автоматически рассчитывает всё при изменении любого параметра. Новые этапы требуют явного запуска подбора и независимого редактирования помещения.

**Alternatives considered:** Переписать ядро раскладки — не нужно; пересылать весь документ проекта в существующий API — смешивает хранение черновиков с контрактом корректного многоугольника.

## 2. Действительные координаты и размерные условия

**Decision:** Декартовы координаты в мм, полная точность чисел; округление только в надписях. Вершины, стены и условия имеют стабильные ID, уникальные внутри снимка; одинаковые ID разных снимков обозначают тот же элемент. Порядок обхода сохраняется. Интерьерный угол вычисляется через знаковый поворот `atan2(cross,dot)`, с учётом направления обхода; угол отверстия относится к самому отверстию. SVG инвертирует Y только при отображении.

**Rationale:** `acos` не различает выпуклый и вогнутый угол. Пиксели и изменение масштаба не должны влиять на длины. Ручной ввод, фиксация условия и подтверждение вычисленных значений — три отдельных свойства.

**Alternatives considered:** Хранить размеры только в надписях — расчёт теряет точность; округлять вершины до сетки — нарушает ручные размеры; индекс вершины вместо ID — ломает связи после удаления.

## 3. Согласование размеров

**Decision:** На сервере использовать SciPy `least_squares(method="trf", loss="linear")` как ограниченный по числу шагов генератор кандидата, затем независимо проверять все условия и топологию. Добавить SciPy 1.18.1, целевой Python 3.12–3.14. Dry-run разрешения зависимости на локальном Python 3.14.4 выбрал scipy==1.18.1 без установки пакетов. Это не проверка корректности решателя. Чистый NumPy оставить для текущего раскладчика.

Для изменения длины исключать координаты начала и конца выбранной стены из переменных: начало неизменно, конец равен `start + target_length * previous_direction`. Это временные условия операции, а не новые скрытые фиксации. Для правки внутреннего угла опорными являются конец выбранной стены и направление входящей стены; исходящая часть может перемещаться с соблюдением остальных условий. Изменение ориентации первой стены сохраняет её начало. При перетаскивании целевая вершина закрепляется на выбранной позиции в рамках операции. Противоречащая фиксациям операция остаётся ошибочным черновиком.

При неполном наборе условий стартовать из предыдущего наброска, использовать стабильный порядок ID; не обещать единственное или глобально ближайшее решение. Для операции без позиционной опоры удерживать первую вершину; удерживать исходное направление первой стены только если оно не является редактируемым параметром. Полностью заданную цепочку предварительно строить непосредственно из длин и углов и проверять замыкание. При простом неконфликтном изменении выполнять прямую конструкцию без нелинейного поиска.

Остатки нормируются по единицам длины и угла; отсутствует штраф, разрешающий обмен точности замера на близость к рисунку. Целевая внутренняя точность — 0,0001 мм/°, допустимый верхний предел проверки — 0,1 мм/°. Пользовательские значения никогда не переписываются результатом. Сохранять ориентацию обхода; не принимать зеркальный или пересекающийся кандидат. Бюджет — до 200 вычислений функции на попытку, одна детерминированная стартовая конфигурация, без случайных многократных запусков; исчерпание возвращает `unresolved`, а не успешный результат.

**Rationale:** TRF допускает недоопределённые задачи; численный успех не доказывает геометрическую корректность. Фиксированные опорные координаты нельзя приблизительно реализовать большими весами штрафов. Общий решатель может не найти существующее решение: интерфейс должен отличать это от доказанного противоречия.

**Alternatives considered:** Последовательно растягивать каждую стену — нарушает ранее заданные размеры и замыкание; смешанный штраф за размеры и положение — скрыто искажает замеры; собственный решатель — существенный численный риск; новый CAD/WASM-движок — лишняя интеграция.

**Sources:** [SciPy least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html). Решение о применении и допусках — проектное, а не гарантия библиотеки.

## 4. Проверка и диагностика

**Decision:** Использовать существующий Shapely, но отдельно проверять пары сегментов для привязки ошибки к ID стен. Соседние сегменты могут иметь только общий конец, несоседние — не пересекаться и не касаться; отверстия строго внутри и попарно раздельны. Никакого автоматического `make_valid` или ремонта буфером. Черновик структурно может быть неполным/геометрически неверным.

Статусы: `valid`, `incomplete`, `constraint_conflict`, `invalid_topology`, `unresolved`. Последний означает, что согласованную форму найти не удалось, а не что её не существует. В диагностике — затронутые стены, вершины, условия, ожидаемое и фактическое значения. Минимальное множество конфликтующих условий не обещается.

Введённые углы 0°, 180°, 360° запрещены спецификацией. Вычисленный угол 180° у старой промежуточной коллинеарной вершины не повод молча удалять её и менять старый проект: сохранить координаты, предложить удалить лишнюю вершину; не создавать фиксированное условие 180°.

**Alternatives considered:** Одна строка `explain_validity` — недостаточно для выбора стены; автоматически чинить многоугольник — меняет замеры.

**Sources:** [Shapely predicates](https://shapely.readthedocs.io/en/2.0.2/predicates.html), [is_valid_reason](https://shapely.readthedocs.io/en/stable/reference/shapely.is_valid_reason.html).

## 5. Состояния этапов и асинхронность

**Decision:** Один владелец состояния проекта, чистый reducer действий и явно выделенные эффекты. Области этапов монтируются условно, а не скрываются только стилями. `documentRevision`, `draftRevision`, `inputRevision` и отдельные operation ID не взаимозаменяемы. Каждый ответ проверяется по проекту, ревизии и операции; отмена запроса дополняет эту проверку. Просмотр предыдущего этапа во время подбора отменяет автоматический переход к результатам.

**Rationale:** Прежний набор независимых `useState` и счётчик только раскладки не описывают проверку черновика, подтверждение и сохранение. Чистая модель действий локализует переходы.

**Alternatives considered:** Только AbortController — не защищает от уже пришедшего ответа; четыре раздельных формы с копиями проекта — риск расхождения. Новая библиотека состояния не требуется.

**Source:** [React: extracting state logic into a reducer](https://react.dev/learn/extracting-state-logic-into-a-reducer).

## 6. Автосохранение, импорт и экспорт

**Decision:** Версионированный документ v2 с независимыми `draft` и `confirmed`. Один формат полезных данных для браузера и файла. Импорт не переносит documentRevision: замена проверяет местную ревизию r с момента предпросмотра и сохраняет r+1, новая запись получает 0. Результаты раскладки живут только в памяти: после перезапуска или импорта Results становится Rules, если предпосылки выполнены. В каталог v2 мигрировать v1 без удаления оригинала; повторная миграция не дублирует записи.

Сохранять завершённые действия до уведомления «Сохранено»; движение указателя и неприменённый текст поля не сохраняются. Допустимы неверные числовые значения в черновике; нечисловой применённый ввод хранится как текст поля, не как NaN. Импорт проверяет структуру локально, без вызова раскладчика, поэтому ошибочный черновик переносим и при недоступном сервере. Геометрическая проверка выполняется отдельно перед подтверждением.

Для нескольких вкладок — Web Lock на запись каталога, свежая загрузка каталога внутри блокировки и проверка revision конкретного проекта. Конкурирующая правка того же проекта не перезаписывается: текущий черновик остаётся в памяти с предложением перечитать сохранённое или скачать копию. При отсутствии Web Locks режим редактирования ограничить одной вкладкой и не обещать согласованную многовкладочную запись.

**Rationale:** Текущая `validateFile` выкидывает неизвестные поля и не принимает короткие контуры, импорт вызывает `/layout`. Это несовместимо с выбранным пользователем полным черновиком. Ошибки квоты/доступа к хранилищу должны сохранять рабочую копию в памяти.

**Alternatives considered:** Новая база данных/серверное хранение — вне объёма; хранение результатов — лишняя сложность и место; миграция поверх v1 — риск потери исходного файла.

**Sources:** [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [MDN Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API). Политика конфликтов и формат v2 — решения проекта.

## 7. Проверки и нерешённые вопросы

**Decision:** Только короткие Playwright e2e, как потребовал пользователь; по прямому запрету FR-029 performance-, нагрузочные, стресс-тесты и бенчмарки не добавлять и не запускать, в том числе через общие команды. Сборка проверяет типы. Численная и UI-корректность проверяются через контрольные комнаты и наблюдаемые результаты в браузере.

**Rationale:** Требуемые гарантии можно проверять малыми сквозными примерами; FR-029 прямо запрещает performance-, нагрузочные и стресс-тесты и бенчмарки, включая их косвенный запуск.

**Alternatives considered:** Отдельная большая программа бенчмарков и unit/property suites — не входят в согласованный способ проверки.

Блокирующих неопределённостей для планирования не осталось. Совместимую сборку SciPy и контрольные геометрические сценарии необходимо проверить в реализации до включения редактора; отказ локального решателя остаётся предусмотренным состоянием, а не поводом менять размеры.

## 8. Повторное планирование после уточнения

**Decision:** Сохранить выбранный стек и решатель; четыре замечания анализа устранить в границах существующей архитектуры. Область уникальности ID — отдельный GeometrySnapshot, включая локальное разрешение ссылок. Импорт использует ревизию назначения: r→r+1 для замены, 0 для новой записи; версия файла не управляет конкуренцией. Предварительный rulesReady проверяет поля, а серверный явный подбор — область после отступа. SC-003 проверяется сравнением данных деталей при фиксированном положении сетки. FR-029 обязателен для всех команд проверки.

**Rationale:** Чтение `backend/planner.py:prepare` подтверждает, что текущий сервер уже проверяет область после gap и ограничение числа ячеек; новый предварительный endpoint не требуется. Снимки комнаты намеренно сохраняют идентичность элементов, поэтому общая для документа проверка дублей неверна. Ревизия файла принадлежит другому контексту хранения. Сравнение содержимого результатов проверяет точность без измерения производительности.

**Alternatives considered:** Глобальная уникальность между снимками ломает round-trip; перенос ревизии из файла создаёт ложный конфликт или откат версии; предварительное вычисление буфера на клиенте дублирует геометрическое ядро; проверка только площади не покрывает детали раскладки. Новые зависимости для этих исправлений не нужны.

Предыдущая проверка разрешения SciPy остаётся свидетельством разрешимости зависимости, а не запуска решателя; повторной установки, запуска приложения или тестов при перепланировании не выполняется. Нерешённых архитектурных вопросов по указанным исправлениям нет.
