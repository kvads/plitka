# Quickstart validation guide

Реализация завершена 2026-10-11: четыре этапа, редактор геометрии и маршруты validate/solve доступны. Ниже — команды запуска и воспроизводимые быстрые сквозные проверки. Требование FR-029 действует для всех последующих изменений.

## Среда и запуск

Из корня проекта: Python 3.12–3.14 (локально 3.14.4), Node.js 20.19+ либо 22.12+, npm, Chromium Playwright. В requirements закреплена SciPy 1.18.1.

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm --prefix frontend ci
```

Если ensurepip отсутствует, использовать `uv venv .venv`, затем `uv pip install --python .venv/bin/python -r backend/requirements.txt`. Не пересоздавать существующее окружение без необходимости.

В двух терминалах:

```sh
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

Открыть http://127.0.0.1:5173; `/api/health` должен возвращать JSON `{"status":"ok"}`. Пустой ответ не считать успешным стартом. Для production preview сначала `npm --prefix frontend run build`, затем перезапустить FastAPI; он раздаёт `frontend/dist`.

## Быстрые проверки

```sh
npm --prefix frontend run build
cd frontend
npx playwright install chromium
npx playwright test tests/projects.spec.ts tests/planner.spec.ts tests/project-stages.spec.ts tests/room-editor.spec.ts tests/project-document.spec.ts
```

Все пять файлов реализованы. Сценарии адаптированы к четырём этапам; проверки ошибок API сохранены. Все тесты — быстрые e2e в изолированных браузерных контекстах, без пользовательского хранилища; один worker, action timeout 5 сек, test timeout 15 сек. По FR-029 запрещено запускать performance-тесты, нагрузочные/стресс-сценарии и бенчмарки, включая их запуск общими командами; состав команд предварительно проверяется. Не запускать pytest; тестовые проверки — только быстрые e2e.

## Контрольные сценарии и ожидаемые результаты

| ID | Действия | Ожидаемый результат / требования |
| --- | --- | --- |
| E01 | Создать проект, открыть Object, пройти Tile → Rules → Variants | Одна рабочая область; назад без потери ввода; неподготовленные этапы недоступны (FR-001–004,019–022) |
| E02 | Нарисовать и численно задать прямоугольник 4200×3600; подтвердить размеры | 15,12 м²; длины ±0,1 мм, углы ±0,1°; без подтверждения derived переход блокируется (FR-009–011,016–018) |
| E03 | Параллелограмм 4000×3000, углы 60°/120°; масштаб 50/100/200% | Площадь 10,392305±0,001 м²; координаты помещения, координаты деталей и метрики раскладки при одном acceptedPlacement не меняются при zoom 50/100/200% и ширине 375/1440; сравнивать содержимое, не скорость (SC-002–003) |
| E04 | На заранее видимой сетке поставить вершину в узел и в середину горизонтальной/вертикальной линии; длина 3175 | Узел и линии различимы; вторая координата на линии не округляется; ручная длина точна (FR-006–008, SC-004) |
| E05 | Свободная стена 3000 → 3500, затем закрепить несовместимые размеры прямоугольника | Начало и направление неизменны, конец +500; конфликт не меняет заданные числа; снять условие/Undo и исправить (FR-012–013) |
| E06 | Г-образный контур с углом 270°, корректное отверстие; затем самопересечение, наложение, касание, отверстие снаружи | Валидная вогнутая форма принимается; каждый отрицательный случай выделяет нужные стены и блокирует confirm (FR-014–015) |
| E07 | Оставить две стены, неверное применённое число и конфликт; дождаться «Сохранено», reload | Точный черновик восстановлен, confirmed не подменён, дальнейший переход запрещён (FR-003,016) |
| E08 | Закончить размеры, подтвердить derived, сохранить/reload; изменить одну вычисленную длину | Неизменный набор сохраняет approval; изменённый требует нового подтверждения (FR-016) |
| E09 | Скачивание/импорт v2 при неполном черновике; файл старого bare Project; повреждённый и будущая версия | Полный v2 восстановлен без результатов; ID между снимками допустимы, дубли внутри снимка отвергаются; при замене локальная ревизия r→r+1 независимо от ревизии файла, при новом импорте 0; изменение после предпросмотра вызывает конфликт; старые координаты без изменения; повреждённый файл не меняет проект (FR-026,028) |
| E10 | Начать подбор; задержать ответ в e2e, изменить геометрию/проект/этап; разрешить старый ответ | Старый ответ не ставит результат и не открывает Results; metadata/zoom не инвалидируют готовый результат (FR-023–024) |
| E11 | Пустой/HTML ответ, сетевой сбой подбора и ручного сдвига; повтор/отмена | Данные не теряются, понятная ошибка, поздний/неуспешный сдвиг не экспортируется (FR-025) |
| E12 | Отказать setItem, затем восстановить; открыть две вкладки и изменить тот же проект | Видно «Не сохранено», копия в памяти доступна; конкурентная правка не затирается (FR-003) |
| E13 | Клавиатурой пройти поля/этапы на 375 px, выбрать ошибку и исправить | Нет скрытых полей в Tab; фокус/ошибки связаны; нет горизонтальной прокрутки (FR-027) |
| E14 | Выбрать вариант, подвигать сетку, закрепить, скачать SVG/CSV и JSON | План/ведомость соответствуют acceptedPlacement; JSON не содержит результатов (FR-022,028) |
| E15 | На подтверждённой узкой комнате задать допустимый численно отступ, уничтожающий область, нажать «Подобрать»; затем уменьшить отступ и повторить | До запуска кнопка доступна, проверка области выполняется сервером; ошибка оставляет Rules и ввод, исправление даёт результат (FR-021, US4.4) |

Сценарии не требуют реальных данных пользователя. Серверные отказы эмулируются перехватом отдельного запроса, а положительные проверки размеров проходят через реальный сервер. Подробные поля и gates: [data-model.md](data-model.md), [geometry-api.md](contracts/geometry-api.md), [project-file.md](contracts/project-file.md), [workflow-ui.md](contracts/workflow-ui.md).

При провале геометрического контроля нельзя увеличивать допуски или снимать условия ради успешного теста. Исправить реализацию либо показать предусмотренный unresolved; обязательные простые контрольные фигуры всё равно должны успешно проходить.

Для E03 достаточно небольшой раскладки и параметризованных коротких случаев: сохранить acceptedPlacement, координаты деталей и метрики; изменить только масштаб/окно и сравнить те же данные. Не сравнивать пиксельный размер SVG и не измерять время. Для E09 разделить round-trip, область ID и локальные ревизии на отдельные быстрые сценарии, чтобы каждый оставался в общем лимите 15 секунд. Ни один сценарий не должен использовать максимум вершин/ячеек ради проверки скорости.


## Результаты реализации, 2026-10-11

- Среда проверки: Python 3.14.4, SciPy 1.18.1, React 19, Chromium Playwright; реальный FastAPI на 8000 и Vite на 5173. Другие версии Python и браузеры не запускались.
- `npm --prefix frontend run build` — успешно: TypeScript и production-сборка Vite.
- Из `frontend`: `npx playwright test tests/projects.spec.ts tests/planner.spec.ts tests/project-stages.spec.ts tests/room-editor.spec.ts tests/project-document.spec.ts --reporter=line` — **46 passed** (22,1 с, один worker). Это время обычного функционального прогона, не измерение производительности.
- После финальной правки полей новой вершины: сборка повторно успешна; `npx playwright test tests/project-document.spec.ts tests/room-editor.spec.ts --reporter=line` — **27 passed** (10,9 с). В том числе нечисловой ввод новой вершины сохраняется в поле и блокирует добавление вместо использования прежней координаты.
- E01/E07–E09/E12: один открытый этап, gates, точная миграция legacy, полный файл v2 без вариантов, draft/confirmed/pendingEdit, восстановление и отмена операции после reload, импорт с локальными ревизиями, отказ хранилища и конфликт двух вкладок.
- E02–E06/E08: ввод размеров прямоугольника 4200×3600 и параллелограмма 4000×3000 с углами 60°/120° проходит через реальный solve. Получены 15,12 и 10,392305 м²; проверены опоры, 3175 мм вне сетки, рефлексный угол 270°, fixed/снятие фиксации/Undo, пересечения, наложение, нулевая стена и касающееся отверстие. Привязка к узлу, обеим линиям и свободная точка проверены на шаге 500 мм: середина линии находится вне установленного радиуса узла 8 CSS px.
- E03: координаты геометрии, деталей и метрики неизменны при масштабе 50/100/200% и ширине 375/1440 px; сравниваются числовые данные, не скриншоты.
- E10/E11/E14: поздние ответы optimize/solve/layout не подменяют актуальное состояние; пустой/HTML/оборванный JSON и сетевой отказ дают понятную ошибку; повтор работает. Сдвиг, отмена, фиксация и скачивание SVG/CSV/JSON проверены.
- E13/E15: путь с клавиатурой и исправлением поля на 375 px; фокус заголовков и отсутствие горизонтальной прокрутки. Численно допустимый отступ проверяется сервером; после ошибки исчезнувшей области исправление даёт раскладку.
- Визуально просмотрены редактор с отверстием и результаты на 375/1440 px. Масштаб отображения отделён от размеров в миллиметрах; подписи и точки сохраняют экранный размер.
- Команды и package scripts просмотрены перед запуском: только build/typecheck и указанные быстрые e2e. **Performance, нагрузочные, стресс-тесты, бенчмарки и pytest не запускались.**
- Первоначальные проверки новых этапов ожидаемо падали до реализации. Выявленные ошибки статуса автосохранения и фиксации неизменённого размера исправлены; неверные ожидания асинхронной записи и подпись поля в тесте уточнены. После исправлений весь набор проходит.
- Решатель ограничен одной попыткой TRF и 200 шагами; невозможность найти допустимую форму остаётся явным `unresolved`, не ослабляет допуск 0,1 мм/° и не меняет confirmed. Полностью заданные цепочки имеют прямую конструкцию и отдельную диагностику конфликта замыкания.
- Новые проекты получают UUID; при миграции сохраняется исходный локальный ID, включая старые идентификаторы без UUID, чтобы не ломать ссылки на проекты.
- Extension hooks до/после implement отсутствуют: `.specify/extensions.yml` не создан.
