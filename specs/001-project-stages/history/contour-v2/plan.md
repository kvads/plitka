# Implementation Plan: Поэтапный проект и точная геометрия помещения

**Feature**: `001-project-stages` | **Date**: 2026-10-11 | **Spec**: [spec.md](spec.md)

**Branch**: setup-plan сообщает `001-project-stages` по выбранной функции. Git-репозитория в рабочей папке нет; ветка не создана.

**Input**: `specs/001-project-stages/spec.md`, включая исходные четыре ответа, последующее исправление I1/U1/U2/C1 и обязательное FR-029. Повторное планирование выполнено 2026-10-11 после уточнения; реализация не начата.

## Summary

Разделить проект на четыре этапа: объект, плитка, правила и варианты. В каждый момент показывать одну рабочую область. Выделить редактор помещения с сеткой, привязкой к узлам и линиям, числовыми длинами и внутренними углами, независимыми от масштаба изображения.

Хранить черновик отдельно от подтверждённой геометрии. Согласовывать условия серверным решателем и независимо проверять кандидат перед подтверждением. Существующий раскладчик получает проверенные координаты в миллиметрах. Расширить автосохранение и файл до версии 2; результаты остаются в памяти и после загрузки подбираются заново.

## Technical Context

**Language/Version**: Python 3.12–3.14 (локально 3.14.4), TypeScript 5.9, React 19.2.

**Primary Dependencies**: существующие FastAPI, Uvicorn, Shapely 2, NumPy 2, Vite 7, lucide-react; добавить SciPy 1.18.1 для least_squares. Разрешение зависимости проверено dry-run; установка и работа решателя проверяются при реализации. Управление состоянием — reducer React без новой библиотеки.

**Storage**: localStorage, каталог `plitka-projects-v2`, переносимый JSON v2, исходные legacy-ключи как резервная копия. Без серверной БД.

**Testing**: только короткие Playwright e2e с небольшими контрольными комнатами и сборка frontend для проверки типов. FR-029 запрещает запуск performance-тестов, нагрузочных/стресс-тестов и бенчмарков, включая запуск через общие команды. Дополнительные unit/property-наборы не входят в план.

**Target Platform**: существующее локальное веб-приложение; современный браузер, ширина интерфейса 375 и 1440 px. Без Web Locks согласованная запись из нескольких вкладок не обещается.

**Project Type**: React frontend + Python API.

**Performance Goals**: движение вершины предварительно обрабатывается локально, сервер вызывается после завершённого действия. Решатель ограничен одной детерминированной попыткой и 200 вычислениями функции. Это проектные ограничения, не измеренные показатели скорости; бенчмарки не проводятся.

**Constraints**: никакого молчаливого изменения введённых размеров; предел ошибки 0,1 мм/°, внутренняя цель 0,0001 мм/°. Автосохранение завершённых ошибочных действий до ответа сервера. Миграция без изменения координат. Файл/запрос геометрии ≤2 МиБ. Старые ответы не меняют актуальное состояние. Нечисловой применённый ввод хранится текстом.

**Scale/Scope**: одна комната на проект, прямые стены, до 100 вершин на контур, 20 отверстий; рабочие координаты ±100000 мм. Лимит раскладчика — 1600 ячеек. Список проектов с названием/адресом остаётся главным экраном. Несколько комнат, облачное хранение, новая авторизация и переработка оптимизатора вне объёма.

## Phase 0 — Research completed

[research.md](research.md) фиксирует решения и альтернативы. SciPy предлагает кандидат, отдельные проверки размеров и Shapely определяют пригодность. Локальная неудача означает unresolved, а не доказанную несовместимость. При вводе длины начало и направление стены сохраняются точно; свободные элементы могут перемещаться.

Документ v2 разделяет draft/confirmed и подтверждение конкретного набора вычисленных размеров. Завершённое намерение правки сохраняется до ответа сервера. Миграция не вызывает раскладчик и не изменяет координаты.

Уточнения после анализа: ID уникальны внутри снимка, одинаковые ID разных версий разрешены. При импорте используется локальная ревизия (замена r→r+1, новая запись 0), не ревизия файла. Guards запуска проверяют числовые правила; область после отступа проверяет сервер при явном подборе. SC-003 включает сравнение координат деталей и метрик раскладки при неизменном смещении, не только комнаты.

## Implementation sequence for task generation

1. Подготовить общие типы v2, reducer, ключи, validate и транспорт. Проверка документа различает ошибки структуры и геометрически неверный черновик; ID проверяются внутри каждого снимка. Эти основания нужны для переходов уже в US1.
2. US1: подключить миграцию, импорт/экспорт и автосохранение, выделить четыре этапа с базовым явным подбором на существующей геометрии. Это первый MVP, без заявления о готовности нового редактора. Сохранить исходные legacy-ключи; импорт назначает местную ревизию и защищён проверкой версии с момента предпросмотра.
3. US2 → US3: внедрить полотно, привязку, команды контуров, solver, инспектор и подтверждение размеров. Сначала короткие контрольные сценарии; опоры и каждый фиксированный размер проверяются независимо от результата численного поиска. Сохранять завершённые действия до ответа сервера.
4. US4: завершить формы материала/правил; может разрабатываться после US1 независимо от US2/US3. До запуска проверять числа и готовность комнаты, а допустимость отступа и лимит ячеек — в явном серверном подборе.
5. US5: завершить результаты, ручной сдвиг, токены и экспорт после US3/US4. Для SC-003 сравнить не только комнату, но координаты деталей и метрики при неизменном acceptedPlacement после zoom/resize.
6. Завершить доступность и выполнить сборку и явно перечисленные короткие e2e из quickstart. Перед запуском проверить состав команд на FR-029; запрещённые наборы не запускать даже как зависимость общей команды.

Порядок соответствует существующим T001–T046; детальные задачи и отметки выполнения остаются в tasks.md. Эта команда заканчивается проектированием, без реализации и запуска тестов.

## Verification and risks

US1 проверяется переходами и восстановлением; US2 — сеткой и топологией; US3 — длинами, углами и фиксацией; US4 — материалом и правилами; US5 — подбором, актуальностью и экспортом. Quickstart отдельно покрывает полный файл FR-028 и миграцию FR-026. SC-001–SC-009 проверяются небольшими e2e, включая площади прямоугольника 15,12 м² и параллелограмма около 10,392305 м².

Численный поиск не гарантирует нахождения каждой допустимой формы: ошибка сохраняет условия и confirmed, оставляет исправление и повторение. Простые контрольные фигуры должны успешно проходить до принятия реализации. Совместимость SciPy установкой и браузерные сценарии пока не проверены; dry-run их не заменяет.

При отказе localStorage копия остаётся в памяти со статусом «Не сохранено» и доступным скачиванием. Конкурирующая правка останавливает автозапись; автоматического слияния геометрии нет. Импорт пересчитывает ключи и проверяет геометрию перед расчётом.

## Complexity Tracking

Нарушений принятых требований нет. Численная зависимость обоснована сохранением длин и углов; отдельный geometry API и модель документа нужны для некорректных черновиков. Дополнительные сервисы и библиотеки состояния не вводятся.
