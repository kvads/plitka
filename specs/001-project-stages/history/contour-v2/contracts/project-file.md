# Project file and storage contract v2

## Переносимый файл

JSON, UTF-8, расширение `.json`, имя скачивания `plitka-project.json`. Envelope:

```json
{
  "format": "plitka-project",
  "version": 2,
  "project": "ProjectDocument по data-model.md; здесь обозначение, не буквальная строка"
}
```

`project` — объект ProjectDocument, а не строка из иллюстрации. Все поля документа обязательны; nullable поля допускают null, runtime поля исключены. Никаких рассчитанных variants, selectedVariant, acceptedPlacement, сетевых токенов, ошибок сервера и Undo-истории. Сохранённый незавершённый геометрический запрос представлен как намерение редактирования, без requestId сервера.

Экспорт разрешён с некорректным draft и устаревшей раскладкой. Экспорт планов SVG и ведомостей CSV — отдельные действия и требуют актуального успешного результата.

Ограничение файла — 2 МиБ для нового формата и legacy. Лимиты строк, ссылок, числа элементов и конечности чисел проверяются до установки данных. Неизвестный format/version, повторяющиеся ID внутри одного GeometrySnapshot и ссылки на отсутствующую стену — повреждённый документ, а не редактируемая геометрическая ошибка. Геометрически неверный, но структурно корректный draft принимается. Совпадения ID между draft, confirmed.geometry и pendingEdit.basisGeometry допустимы; все ссылки проверяются в пределах своего снимка.

## Импорт

1. Прочитать файл и проверить структуру без `/layout` или `/optimize`.
2. Распознать v2 либо прежний bare Project с outline/holes/tile/grout/gap/threshold/angle/offset_x/offset_y. Не угадывать неизвестную будущую версию.
3. Показать название, адрес и действие «Заменить открытый проект». Только применение меняет проект; отмена оставляет его нетронутым. На главной странице действие «Импортировать проект» создаёт новую запись.
4. При замене сохраняется локальный ID открытого проекта, данные и метаданные берутся из файла. При создании назначается новый ID; внутренние ID геометрии сохраняются. Ревизия documentRevision из файла не переносится: при замене сохранить ожидаемую локальную ревизию r на момент предпросмотра, проверить её под Web Lock и записать r+1; при изменении записи за это время показать конфликт. Новый импортированный проект записывается с documentRevision=0, последующие сохранения увеличивают её. Импорт одного файла дважды создаёт две независимые записи только по двум явным действиям пользователя.
5. Сохранить новый документ целиком; при отказе хранилища прежняя сохранённая запись не меняется, предложить повторение. Текущий пользовательский черновик не терять.
6. Runtime результаты очистить. Пересчитать keys, диагностику и доступность этапов. Неподтверждённая комната → object; невалидный материал → tile; variants без результата → rules. Геометрическая проверка сервера может выполняться после импорта; её недоступность не мешает сохранить документ, но блокирует подтверждение и подбор.

Для legacy bare файла metadata отсутствует: при замене оставить название/адрес открытого проекта, при создании — «Импортированный проект», адрес пустой. Все координаты и числовые параметры сохранить точно; старые offsets сохраняются только в исходной резервной копии legacy-данных, не считаются восстановленным новым результатом. Пользователь должен заново подтвердить геометрию и выполнить подбор. Старые исходные JSON можно хранить в исходном legacy ключе, не включать offsets в новые правила.

## Каталог браузера

Ключ `plitka-projects-v2`; значение `{schemaVersion:2, projects: ProjectDocument[]}`. Служебный `documentRevision` каждого проекта растёт по завершённой записи.

Автосохранение выполняется после каждого завершённого действия, включая незамкнутый контур, отрицательный размер и применённое нечисловое поле. Порядок: вычислить следующий документ в памяти → захватить Web Lock `plitka-projects-write` → прочитать актуальный каталог → проверить ожидаемую documentRevision изменяемого проекта → заменить только его запись → сериализовать и записать один ключ → объявить «Сохранено». Метаданные одного объекта не могут затереть свежий план другого.

Если та же запись уже обновлена другим редактором, не делать last-write-wins: остановить автозапись, показать конфликт и сохранить свою копию в памяти для скачивания. Доступны «Загрузить сохранённую версию» и «Скачать мой черновик». Принудительное автоматическое слияние геометрии не входит в объём. Без Web Locks допускается работа в одной вкладке; при обнаруженном событии storage с новой ревизией того же проекта остановить запись и показать конфликт, не обещая межвкладочной транзакционности.

При QuotaExceededError/SecurityError: последний успешный документ остаётся в хранилище, новый — в памяти, видимый статус «Не сохранено», повторная попытка и экспорт. Не показывать успешное сохранение заранее. Автосохранение не ждёт проверки геометрии сервером. При refresh может потеряться только незавершённое действие либо явно обозначенная несохранённая правка.

## Миграция

Порядок чтения: валидный v2 → v1-каталог → legacy одиночный проект → пустой список. При наличии повреждённого v2 нельзя молча падать на v1 и перезаписывать данные: показать восстановление/скачивание исходных данных.

Миграция каталога — единая запись v2 после проверки всех документов. До успеха не удалять/не менять старые ключи. Сохранить ID, название, адрес старых записей; новым стенам/вершинам назначить ID один раз. Никаких fixed условий или acknowledgment «по умолчанию»; confirmed отсутствует. Штатный путь миграции не меняет ни одной исходной координаты. Ошибка одной записи не удаляет остальные и не записывает частично мигрированный каталог.
