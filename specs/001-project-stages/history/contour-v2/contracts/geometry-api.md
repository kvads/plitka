# Geometry API contract (проект)

Существующие `/api/health`, `/api/layout`, `/api/optimize` сохраняют формат. Новые маршруты не сохраняют проекты на сервере. Текст сообщений — русский; машинные коды стабильны. Единицы — мм и градусы.

## POST /api/geometry/validate

Запрос: `{requestId: string, draftRevision: integer, geometry: GeometrySnapshot}` из data-model.md. Открытые и геометрически неверные черновики структурно разрешены. validate не перемещает вершины и не меняет условия.

Ответ HTTP 200: `{requestId, draftRevision, validation: ValidationResult}`. Возвращаются измерения всех определимых стен, диагностические ID, площадь только при корректном замкнутом помещении. Проверяются фиксированные размеры независимо от статуса solver. Полный measurement набор используется для пользовательского подтверждения.

Структурно некорректный запрос: HTTP 422 с `{detail: string, code:"INVALID_GEOMETRY_DOCUMENT", issues: Issue[]}`. Слишком большой документ: HTTP 413. Геометрический конфликт сам по себе не является HTTP 500/422.

## POST /api/geometry/solve

Запрос: `{requestId, draftRevision, geometry, operation}`. geometry содержит исходные координаты и текущие условия до операции; operation — намерение пользователя. UI отдельно сохраняет применённое намерение в draft до ожидания ответа. Каждый ответ проверяется против ревизии, к которой относится операция.

| operation.type | Поля | Обязательное поведение |
| --- | --- | --- |
| `setLength` | wallId, value | закрепить начало и новое положение конца вдоль прежнего направления на время операции; обновить fixed length |
| `setInteriorAngle` | wallId, value | сохранить конечную вершину выбранной стены и её входящее направление; изменить внутренний угол со следующей |
| `setOrientation` | contourId, value | сохранять первую вершину, изменить направление первой стены |
| `moveVertex` | vertexId, x, y | попытаться совместить вершину с целью без удаления fixed условий |
| `releaseConstraint` | constraintId | снять фиксацию, не удалять пользовательское происхождение |
| `reconcile` | нет | решить текущие сохранённые условия от текущего наброска без новой правки |

Ответ HTTP 200: `{requestId, draftRevision, geometry: GeometrySnapshot, validation: ValidationResult, changedWallIds: string[]}`. При valid geometry — согласованный кандидат с полными координатами. При остальных статусах geometry сохраняет введённые условия и безопасный исходный/предварительный набросок; confirmed никогда не меняется. Применённые значения не переписываются фактически достигнутыми размерами. Поля ответа — предложение обновить draft, не команда автоматически подтвердить помещение.

`constraint_conflict` — установленное противоречие (например, замыкание полностью заданной цепочки). Если численная попытка не нашла допустимый результат, статус `unresolved` и сообщение «Не удалось найти согласованную форму; проверьте отмеченные размеры или снимите фиксацию». Независимо от статуса SciPy принять valid можно только после проверки размеров, знаковых углов, ориентации и топологии.

Для открытой цепочки solver может согласовать введённые условия, но итог validation остаётся incomplete до явного замыкания. Неверные числовые значения и fieldInputs не отправлять в численную оптимизацию: возвращать диагностику.

## Общие ограничения и отказы

- ID элементов уникальны внутри переданного GeometrySnapshot, ссылки локальны этому снимку; одинаковые ID в разных сохранённых снимках допустимы.
- Геометрия: до 100 вершин на контур, 20 отверстий, 3 вида условий на стену (ориентация только первой), ID не длиннее 100 символов; тело до 2 МиБ.
- Рабочие координаты ±100000 мм. Нечисловой ввод может присутствовать в fieldInputs (строки до 100 символов), но запрещает valid.
- Пустая геометрия возвращает incomplete; исключения GEOS/решателя не превращаются в пустой успешный ответ.
- Неожиданная серверная ошибка: HTTP 500 с понятным `detail` и requestId; лог без названия/адреса и полного документа. Транспортные сбои/HTML-ответы прокси обрабатываются существующим надёжным JSON-клиентом, расширенным валидаторами каждого вида ответа.
- На завершённое действие — один solve/validate запрос. Движение указателя даёт локальный предварительный рисунок, не поток серверных задач. Время ожидания интерфейса ограничить 10 секундами; Abort и `unresolved`/сообщение не разрешают дальнейший переход. Проверка времени — рабочий предел, не план performance-тестов.
- Успешный validate при открытии импортированного confirmed не меняет координаты. Подтверждение и следующий расчёт используют один и тот же снимок. Для файла с неподтверждёнными размерами сохраняется ручной gate.

## Адаптер к существующему раскладчику

Из `confirmed.geometry` извлечь ordered outline/holes без повторения последней вершины; добавить tile, grout, gap, threshold, angle. Для `/optimize` offset_x/offset_y=0; для `/layout` — только положение, выбранное на этапе вариантов. Не отправлять название, адрес, draft, constraints и viewport в прежний Project request: он запрещает extra-поля.

Оба старых расчётных маршрута по-прежнему проверяют многоугольник. Клиент не может вызвать их из нового UI, пока roomReady/materialReady/rulesReady не выполнены. rulesReady означает только корректные числовые поля правил и отсутствие их fieldInputs. Допустимость области после отступа и лимит ячеек проверяются самим optimize/layout при явном запуске; отдельная предварительная проверка и вычисление буфера на клиенте не нужны. Ошибка сохраняет ввод и не допускает перехода к результатам; для ручного сдвига сохраняется последний acceptedPlacement, экспорт pending блокируется. Схема ответа существующих маршрутов не меняется.
