# Data model

Все новые структуры ниже проектируются для реализации; существующий плоский `Project` переименовывается в `LayoutRequest` только на клиенте. Единицы: мм, градусы, площадь интерфейса — м². Координаты хранятся без округления.

## ProjectDocument v2

| Поле | Тип / смысл |
| --- | --- |
| `schemaVersion` | literal `2` |
| `id` | UUID локального проекта |
| `name`, `address` | строки, 1–120 символов для имени после trim, 0–300 для адреса |
| `documentRevision` | целое ≥0, меняется при каждой сохраняемой операции |
| `room` | RoomState |
| `material` | `{tile, grout}`; применённые значения, в черновом документе могут быть вне рабочего диапазона |
| `rules` | `{gap, threshold, angle}` |
| `fieldInputs` | словарь применённого нечислового/пустого ввода по пути поля; блокирует использование соответствующего раздела, сохраняет текст |
| `workflow` | `{requestedStage: object\|tile\|rules\|variants}` |
| `viewport` | `{centerX, centerY, zoom, gridStepMm}`; не участвует в расчёте |

Поля статуса сохранения, активный указатель, выделение, Undo-стек, диагностика и результаты сервера — runtime. Предусмотреть локальный Undo последних завершённых действий текущей сессии, минимум 20 снимков; каждый снимок включает условия и подтверждения. После перезапуска доступны текущий сохранённый черновик и отказ от него в пользу confirmed; история Undo не обещается.

## RoomState

- `draft: GeometrySnapshot`: всегда есть, может быть пустым, незамкнутым, конфликтующим.
- `draftRevision: integer`: монотонная ревизия геометрии/условий/применённого геометрического ввода.
- `pendingEdit: {operation, basisGeometry, targetDraftRevision} | null`: намерение согласования, operation из контракта solve, basisGeometry — снимок до операции. Сетевые ID не сохраняются.
- `confirmed: ConfirmedRoom | null`: отдельная глубокая копия последней подтверждённой геометрии; никакого совместного изменения ссылок с draft.
- `acknowledgment: {measurementKey, entries} | null`: явно подтверждённый набор вычисленных размеров. `entries` — отсортированный список `{wallId, kind, displayedValue}`. Подтверждение не создаёт фиксированные условия.

Завершённая правка немедленно сохраняет введённые условия и предварительное положение в draft вместе с pendingEdit. Solve получает basisGeometry и operation. Только актуальный успешный ответ заменяет draft и очищает pendingEdit; ошибка сохраняет намерение для явного повторения. Следующая правка заменяет pendingEdit, используя текущий draft за основу; отказ от черновика очищает его. После загрузки pendingEdit блокирует подтверждение до успешного согласования или явной отмены.

`ConfirmedRoom` содержит `geometry`, `geometryKey`, `measurementKey`, `acknowledgment` и `sourceDraftRevision`. `geometryKey` — каноническое представление всей геометрии и условий без viewport и метаданных; это сравнение содержимого, не дата сохранения. Служебные ключи пересчитываются при загрузке, значения из файла не считаются доказательством валидности.

`measurementKey` включает ID/вид вычисленного размера и показанное с точностью 0,1 значение, а также ключ исходной геометрии. Любая геометрическая правка сбрасывает допуск к расчёту; при изменении вычисленных значений сбрасывается acknowledgment. Если значение изменилось меньше точности надписи, всё равно требуется повторная проверка геометрии и подтверждение текущего набора, поскольку исходная геометрия отличается. Смена масштаба, названия, адреса и этапа ключи не меняет.

## GeometrySnapshot, Contour, Vertex, Wall

`GeometrySnapshot = {outer: Contour, holes: Contour[], constraints: DimensionConstraint[], fieldInputs}`.

`Contour = {id, kind: outer|hole, closed: boolean, winding: ccw|cw, vertices: Vertex[], walls: Wall[]}`.

- `Vertex = {id, x, y}`; ID уникален внутри одного GeometrySnapshot, числа конечны. Вершины упорядочены, первая не дублируется в конце. Уникальность ID контуров, вершин, стен и условий проверяется отдельно в каждом GeometrySnapshot; одинаковые ID в draft, confirmed.geometry и pendingEdit.basisGeometry допустимы и обозначают тот же элемент. Ссылки разрешаются только внутри своего снимка.
- `Wall = {id, startVertexId, endVertexId}`; ссылается на соседние вершины своего контура; в открытой цепочке n−1 стен, в закрытой n. При добавлении/удалении назначать новые ID только новым элементам; не перенумеровывать существующие ID.
- Удаление вершины заменяет прилегающие стены новой. Связанные условия показываются как удаляемые вместе с выбранным элементом до действия; никогда не перепривязываются к случайной стене. Undo возвращает исходные ID и условия.
- `winding` новой заготовки — ccw. При замыкании свободного наброска вычислить его знак; после этого сохранять порядок, не разворачивать фигуру автоматически. Для открытой цепочки переключение стороны внутренних углов явно меняет winding, а не переставляет вершины.
- Пустой/неполный draft допустим структурно. Для принятия: ≥3 различных вершин, положительные стены, площадь >0, валидная топология. Лимиты наследуются: 100 вершин на контур, 20 отверстий, координаты ±100000 мм. Геометрически неверные конечные значения вне рабочего диапазона можно хранить в draft, но нельзя решать/подтверждать.
- Закрытие — отдельное действие; система не добавляет скрытую «корректирующую» стену для компенсации противоречивых заданных длин.

## DimensionConstraint и измерения

`DimensionConstraint = {id, kind: length|interiorAngle|firstWallOrientation, wallId, value, fixed}`.

- Вручную введённое значение создаёт/обновляет единственное условие данного kind для стены и устанавливает `fixed=true`.
- `fixed=false` сохраняет происхождение старого ввода, но не ограничивает решатель. Надпись в этом случае показывает фактическое вычисленное значение, а не старое снятое условие.
- Числа конечны, длина >0, внутренний угол строго между 0° и 360°, кроме 180°; направление первой стены — угол по модулю 360°. Неверные значения сохраняются в draft и имеют ошибку; не допускаются к solver.
- `interiorAngle` относится к концу выбранной стены и следующей стене, для последней стены открытой цепочки отсутствует. `firstWallOrientation` допустим только для первой стены контура.
- Вычисленные измерения возвращаются как `{wallId, length, interiorAngle|null, lengthSource, angleSource}`. Значения с неснятым ручным условием имеют source `entered`, остальные — `derived`. Подпись и фиксация не вычисляются из наличия acknowledgment.
- Запятая и точка преобразуются при commit; пустой или нечисловой ввод сохраняется в `fieldInputs`, не превращается в 0/NaN/null. Частично набранный текст до commit — состояние поля.

## ValidationResult

`{status, issues[], measurements[], areaMm2|null, closureGapMm|null}`.

`status = valid | incomplete | constraint_conflict | invalid_topology | unresolved`.

`Issue = {code, message, contourId?, wallIds[], vertexIds[], constraintIds[], expected?, actual?, deviation?, unit?}`.

Приоритет отображения: структурная ошибка → неполнота/неверный ввод → нарушение геометрии/размеров → unresolved. Можно показать несколько проблем одновременно. `valid` означает выполнение всех проверок, не разрешение перехода без acknowledgment и confirm.

## Состояния и переходы

| Событие | Черновик / подтверждение | Результаты и навигация |
| --- | --- | --- |
| Commit геометрии | новая draftRevision, pending validation, автосохранить; confirmed не менять | немедленно закрыть допуск к подбору/экспорту, отменить запросы |
| Пришёл solve текущей версии | сохранить только подходящий по operation ID кандидат и измерения | успешный кандидат ещё не подтверждён |
| Подтверждение вычисленных размеров | сохранить acknowledgment для показанного набора | само по себе не фиксирует стены |
| Подтвердить помещение | только valid, нет fieldInputs, acknowledgment соответствует; копировать в confirmed | открыт этап плитки |
| Отменить правку | восстановить предыдущий полный draft, затем перепроверить | не оживлять устаревший ответ |
| Отказаться от черновика | явно восстановить confirmed; если его нет — пустой draft | выбрать первый доступный этап |
| Commit материала/правил | сохранить значения и ошибки | инвалидировать расчёты, не геометрию |
| Optimize / manual layout | сохранить request token с projectId и inputKey | только ответ актуального токена может обновить runtime result |
| Возврат на ранний этап | сохранить requestedStage; отменить автопереход ожидаемого подбора | скрыть другие рабочие области |
| Повторное открытие | validate сохранённые снимки без изменения координат | requestedStage ограничить доступностью; без runtime result variants → rules |

`roomReady`: draft по содержимому равен confirmed, pendingEdit отсутствует, успешно перепроверен, нет применённых ошибок, acknowledgment подходит. Совпадение только номера ревизии недостаточно.

`materialReady`: tile ∈ [50,2000], grout ∈ [0,20], нет fieldInputs. `rulesReady`: gap ∈ [0,100], threshold ∈ [1,1000], angle ∈ [0,90), нет fieldInputs правил. rulesReady проверяет только ввод правил, не результат геометрического отступа. Область после отступа и лимит раскладки 1600 ячеек проверяет сервер при явном optimize/layout; до ответа разрешён запрос, но не переход к вариантам или экспорт результата. Ошибка остаётся на текущем этапе с сохранённым вводом.

## Runtime result и версии запросов

- `inputKey`: канонические подтверждённые outline/holes + material + rules. `inputRevision` меняется при содержательном изменении расчётных входов; любая незавершённая правка комнаты дополнительно блокирует текущие результаты.
- `requestToken = {projectId, operationId, inputRevision, inputKey}`; для solve вместо input — draftRevision и ключ запроса. AbortController не заменяет сравнение токена.
- `ResultSet = {token, variants, selectedVariantId, acceptedPlacement, pendingPlacement, locked}`; только память.
- Сдвиг сетки принадлежит результату, не помещению. Ошибка ручного пересчёта сохраняет последний успешный результат отдельно от неуспешного ввода; экспорт блокируется до успеха или явной отмены pendingPlacement.
- Новое подтверждение идентичных входов может оставить текущий runtime result актуальным только после повторной проверки guards; не принимать незавершённый старый запрос.

## Хранение и совместимость

Каталог `plitka-projects-v2 = {schemaVersion:2, projects: ProjectDocument[]}`. Один завершённый переход записывает весь новый документ одной заменой каталога после свежего чтения. Ревизия из импортированного файла не используется для локальной записи: замена проверяет ожидаемую текущую локальную ревизию r и сохраняет r+1; новая импортированная запись сохраняется с documentRevision=0. Изменение локального проекта после открытия предпросмотра импорта вызывает конфликт, не перезапись. Проверка documentRevision защищает от тихой записи поверх другого редактора; конкретный протокол описан в contracts/project-file.md.

Миграции распознают `plitka-projects-v1`, одиночный `plitka-project-v1` и старый JSON `Project`. Координаты/размеры не округляются. Новые ID присваиваются один раз и сохраняются. Условия пустые, размеры derived, acknowledgment=null, confirmed=null, requestedStage=object. Старые ключи сохраняются как резервная копия, повторная загрузка v2 не запускает миграцию заново.

Неполные новые файлы принимаются как draft только при корректной структуре. Неизвестная версия, повторяющиеся ID внутри одного снимка, отсутствующие ссылки, бесконечные числа и неверные типы отклоняются до изменения текущего проекта.
