# Research: контекстное редактирование и очистка проекта

Дата: 2026-10-12. Объём: FR-035–FR-038, изменения FR-003/005/008/009/010/027/033, SC-012 и SC-014–SC-017. Повторно исследованы текущие исходники React/FastAPI. Два независимых исследования проверили диапазоны/углы и жизненный цикл/хранилище; результаты сопоставлены с текущими моделями, обработчиками и конфигурацией e2e. Тесты и сборка не запускались. Предыдущий дизайн сохранён в `history/vertex-safety/`. Принятые решения I1/U1 сохранены: запрет ручного 180° и явный выбор диапазона. Проверенные локальные версии: Python 3.14.4 (.venv/pyvenv.cfg), React 19.3.0, TypeScript 5.9.3, Vite 7.3.7, Playwright 1.64.0 (frontend/package-lock.json). Выбор стека не пересматривается.

## R1. Контекст меню отделён от области расчёта

**Decision**: единый runtime reducer хранит выбранный объект и незавершённое взаимодействие инструментом. Сохранённый `selectedRoomId` выбирает область расчёта, но не открывает настройки помещения при выборе стены/вершины. Разделить общую панель на контекстные панели и меню проекта.

**Rationale**: `frontend/src/components/canvas/GraphWorkflow.tsx` хранит независимые vertex/segment/second/sector/panel, а общий aside одновременно показывает комнату, списки и размеры. Эти состояния могут пережить удаление объектов. Reducer проверяет ссылки при принятии результата.

**Alternatives considered**: дополнительные флаги общей формы усложняют взаимоисключение; отдельная страница нарушает единое полотно. Новая библиотека состояния не нужна.

## R2. Клавиатурный выбор на полотне заменяет списки

**Decision**: доступные SVG hit targets и один перемещаемый фокус внутри полотна. Стрелки переключают подходящие инструменту объекты, Enter/Space выбирают; подсветка и доступное название описывают геометрию. Добавление и соединение с промежуточной точкой стены используют клавиатурный курсор. Перемещение вершины — preview стрелками, Enter подтверждает один раз, Escape отменяет. Шаг сетки и точный шаг 1 мм с Shift объясняются в подсказке. Для диапазона действие в контексте сегмента выбирает chainId, затем два разных его узла (rangeFirst/rangeSecond); готовый range context хранит нормализованные по цепи концы. Чужой/повторный узел сохраняет первый выбор, Escape/смена инструмента отменяют выбор, утрата цепи/конца закрывает меню. Поле длины доступно только после пары; G24r проверяет keyboard-путь и отмену без команды.

**Rationale**: `ProjectCanvas.tsx` сейчас имеет SVG role=img, геометрия pointerEvents=none; удаляемые селекты были клавиатурным обходным путём. В полях ввода и модальном подтверждении команды геометрии не обрабатываются.

**Alternatives considered**: скрытые номерные селекты сохраняли бы неясную модель; множество Tab-остановок затруднило бы выход. Простые доступные подписи и roving focus не требуют новой зависимости.

## R3. Угол определяется явной парой и дугой

**Decision**: первая стена → вторая примыкающая → одна из двух дополнительных до 360° дуг → ввод градусов. Общий узел проверяется по ID. Существующие setAngle и solver сохраняются; общая функция строит дуги для картинки, hit targets и клавиатурного выбора. При обратном порядке стен искать эквивалентное существующее условие с обратным сектором, не создавать вторую фиксацию того же угла.

**Rationale**: GraphWorkflow автоматически выбирает первый соседний сегмент; `DimensionOverlay.tsx` показывает одну неинтерактивную дугу. Сервер уже хранит vertexId, два segmentId, cw|ccw. Экранная инверсия Y относится только к отображению. Спецификация и существующий graph_validation запрещают ручное 180°: этот запрет сохраняется вместе с 0°/360°, а вычисленный 180° остаётся derived. Разрешение ручного 180° в предыдущем тексте UI/T164 было противоречием, не новой договорённостью; G31c проверяет отказ без изменения координат.

**Alternatives considered**: селект сектора или автоматический внутренний угол не удовлетворяют явному выбору в узле 3+ стен. acos теряет вогнутые углы.

## R4. Сервер вычисляет предпросмотр удаления

**Decision**: общий чистый расчёт последствий в новом `backend/geometry/deletion.py`; read-only endpoint `/api/plan/deletion-preview` для комнаты/отверстия; deleteRoom и deleteVoid в существующем command endpoint. impactKey связывает исходный граф, цель и полный план удаления. При исполнении последствия вычисляются заново; несовпадение требует нового подтверждения.

**Rationale**: `faces.inspect()` предоставляет точные границы. Для комнаты удаляются face.outer и face.holes, включая общие стены; dependencyIds содержит также чужие участки цепей и потому не является списком удаления. Сервер stateless уже принимает полный граф.

**Alternatives considered**: клиентский список стен и эвристический deletionConditions могут разойтись с реальным каскадом; последовательные команды создают частично удалённый граф и несколько Undo. База данных не нужна.

## R5. Каскад удаления ограничен выбранной геометрией

**Decision**: для комнаты/отверстия удалить границу, только её осиротевшие концы, условия на удалённые элементы/выведенные из обращения цепи и повреждённые записи void целиком. Сохранить стены вне границы, их общие вершины и отдельные точки вне границы. Остатки цепей пересобрать по текущему алгоритму; связанные потери условий включить в preview. Обычное удаление стены сохраняет отдельные концы по прежнему контракту, удаление вершины удаляет инцидентные стены.

**Rationale**: `graph_commands.delete_elements()` уже пересобирает цепи, но обрезает void.boundary, оставляя незамкнутое отверстие. Нужно удалять повреждённую запись целиком. Все изменения и проверка ссылок выполняются на копии.

**Alternatives considered**: глобальная очистка изолированных точек уничтожает независимые наброски; сохранение общей стены противоречит ответу пользователя; перенос полной длины старой цепи на остаток меняет измеренный объект.

**Проектное решение для отверстия**: «Удалить отверстие» удаляет замкнутую границу с предпросмотром, чтобы убрать вырез. Старый unmarkVoid сохраняется как отдельное «Снять отметку отверстия»: он оставляет стены и может создать самостоятельное помещение. Простое снятие роли не убирает вложенное кольцо из внешней грани. Для повреждённого незамкнутого void доступно снятие роли, оставшиеся стены редактируются отдельно. Различие показывается до подтверждения.

## R6. Удаление условия отличается от снятия фиксации

**Decision**: deleteConstraint удаляет запись и относящиеся raw fields, сохраняет координаты и пересчитывает диагностику без solver. releaseConstraint по-прежнему оставляет fixed=false. Это относится и к legacyUnbound: его удаление доступно из карточки диагностики, остальные условия доступны у выбранной геометрии.

**Rationale**: в `graph_models.py` и `graph_commands.py` есть только освобождение. Удаление требования не должно внезапно двигать план, но инвалидирует зависимые результаты по FR-023.

**Alternatives considered**: выдавать освобождение за удаление не выполняет FR-036; запуск solver добавляет неожиданную правку.

## R7. Очистка — действие целого документа

**Decision**: hook-level clearProject сохраняет id/name/address и текущую ревизию записи, заменяет всё рабочее содержимое: emptyGraph, rooms=[], pending/restorePoint/selectedRoom=null, этап object и стандартный viewport. Один снимок Undo — в существующей ограниченной runtime истории. Undo восстанавливает исходные данные, настройки, подтверждения и pending как намерение без запуска; варианты остаются отсутствующими, variants понижается до rules или object по guards.

**Rationale**: текущая ветка восстановления GraphWorkflow очищает только draft, а `rooms.bindRooms()` сохраняет detached записи. Это не полный сброс. Строгая схема v3 уже поддерживает пустой документ.

**Alternatives considered**: удалить проект и создать новый потеряло бы идентичность; сериализованный clear-backup нарушил бы срок жизни Undo; удаление старых localStorage-ключей затронуло бы резервные копии. v3 остаётся источником истины без автоматического fallback.

## R8. Общая эпоха защищает clear → Undo

**Decision**: runtime lifecycle epoch повышается синхронно при clear и Undo clear. Geometry/validate/legacy retry/optimize/layout, deletion preview и importV3/File.text, их error/finally и действия после await проверяют epoch вместе с прежними токенами. Позднее чтение файла не публикует import preview или ошибку после clear, Undo clear и закрытия проекта. Текущий exportResult синхронный: проверять актуальность перед download, не создавать искусственную сеть или await для экспорта. Очередь сохранений имеет epoch; устаревшая запись пропускается также внутри Web Lock до CAS. Уже совершившаяся запись учитывается по ревизии, но её старый payload не публикуется. Только последняя реально записанная версия получает «Сохранено».

**Rationale**: `useGraphProject.ts` и GraphWorkflow имеют независимые поколения запросов. После Undo прежние ключи могут совпасть. `storage.ts` проверяет documentRevision под Web Lock; эту защиту нельзя ослаблять. [GraphWorkflow.tsx](../../frontend/src/components/canvas/GraphWorkflow.tsx) устанавливает preview после await importV3, а [storage.ts](../../frontend/src/domain/plan/storage.ts) читает File.text асинхронно: одного сброса уже открытого preview недостаточно. [result-export.ts](../../frontend/src/domain/project/result-export.ts) формирует SVG/CSV локально и синхронно; G30i проверяет именно поздний импорт.

**Alternatives considered**: AbortController не предотвращает применение уже готового ответа; React effect может запоздать; откат documentRevision обходил бы конкурентность. Ошибка сохранения не откатывает память молча и не снимает конфликт другой вкладки.

## R9. Только быстрые e2e при реализации

**Decision**: адаптировать helpers и применимые сценарии к настоящему выбору на полотне, добавить небольшие случаи удаления, clear/Undo/races и угла. Chromium, один worker, 15 с на тест, 5 с на действие. Build/typecheck допустимы при реализации.

**Rationale**: `frontend/tests/fixtures/projects.ts` и существующие spec-файлы используют удаляемые селекты/пресеты. Скрытые поля ради тестов не проверяют интерфейс. FR-029 запрещает performance/load/stress/benchmark; отдельные pytest/unit/property/contract-наборы не запускаются.

**Alternatives considered**: замена всех UI-проверок прямым API убрала бы проверку взаимодействия; общий тестовый скрипт может косвенно нарушить запрет. На этапе планирования проверки исполнения не выполняются.

## R10. Диапазон использует существующую цель размерного условия

**Decision**: хранить выбор только в rangeFirst/rangeSecond/range context. Канонический порядок концов определяется цепью: её начальный узел, затем конечные узлы segmentIds. Применение числа использует прежний setLength и chainLength.target.range. Поиск существующего условия учитывает kind=chainLength, chainId и оба канонических конца, включая fixed=false; полная длина цепи без range остаётся отдельной целью. Длина диапазона — сумма его участков; при редактировании закрепляется начало диапазона, а не первый клик пользователя.

**Rationale**: [graph_models.py](../../backend/geometry/graph_models.py) требует startIndex < endIndex и запрещает повтор kind+target; [graph_validation.py](../../backend/geometry/graph_validation.py) измеряет непрерывный срез, [graph_solver.py](../../backend/geometry/graph_solver.py) закрепляет его начало. [topology.py](../../backend/geometry/topology.py) сохраняет chainId и существующие концы диапазона при split. Нынешний helper constraint в [GraphWorkflow.tsx](../../frontend/src/components/canvas/GraphWorkflow.tsx) исключает range: для нового контекста нужен отдельный поиск точной цели.

**Decision — отказы**: сохранить действующие категории. Некорректный входной снимок/форма запроса — HTTP 422. Корректный basis с командой, создающей неверные ссылки или порядок range, — HTTP 200/status=invalid и исходный граф. Структурно корректное, но несовместимое размерное условие — HTTP 200/status=unresolved с введённым условием и прежними координатами. Ручные 0°/180°/360° относятся к последнему случаю; raw хранится по текущим правилам клиента, подтверждение геометрии блокируется.

**Rationale**: входной запрос проверяется в [graph_routes.py](../../backend/geometry/graph_routes.py), а проверка GraphSnapshot после apply_condition находится внутри try/except [graph_commands.execute](../../backend/geometry/graph_commands.py). Ошибка кандидата возвращает invalid, не исключение HTTP. Недопустимые конечные углы проходят схему и отклоняются solver. Уточнение документации не меняет обработчики и не делает старые конфликтующие документы нечитаемыми.

**Alternatives considered**: новая сущность/версия файла/API не нужны. Создание нового constraintId для уже существующего released диапазона даст повтор цели; использование полной длины вместо range изменит другой замер. Общее правило «все неверные ссылки → 422» не соответствует действующему разделению входного запроса и результата команды.

## Итог исследования

Все проектные решения определены. Новых библиотек, миграции сохранённых документов и изменений раскладчика не требуется. Установленные React/TypeScript/FastAPI/Shapely/SciPy используются без обновления. Конкретные интерфейсы задаются Phase 1.
