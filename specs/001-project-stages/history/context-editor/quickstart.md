# Quickstart: контекстные меню, удаление, очистка и угол

Дата плана: 2026-10-12. Это руководство проверки FR-035–FR-038 и SC-014–SC-017, а также уточнений I1/U1 для FR-010/033 и SC-012/017. Инкремент **реализован и проверен**; фактические результаты приведены ниже. На этапе планирования тесты и сборка не запускаются. Прежние проверки графовой базы и защиты вершин находятся в [историческом руководстве](history/vertex-safety/quickstart.md) и не подтверждают новый инкремент.

## Подготовка при реализации

Использовать существующие Python-окружение, Node.js/npm и Chromium Playwright. Не переустанавливать зависимости работающего проекта без необходимости. Для новой установки из корня:

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm --prefix frontend ci
```

FastAPI и Vite запускаются в отдельных терминалах, если уже не работают:

```sh
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

Открыть http://127.0.0.1:5173/. Проверять только изолированные проекты в новых браузерных контекстах; пользовательский проект не очищать и не превращать в fixture. /api/health должен вернуть корректный JSON. Положительные geometry/deletion/angle проверки используют настоящий FastAPI; перехваты нужны только для управляемых задержек и отказов.

## Разрешённые команды проверки

Перед запуском проверить package scripts и состав выбранных тестов. Только быстрые функциональные e2e, Chromium, один worker, test timeout 15 с, action timeout 5 с. Performance, load, stress, benchmark, pytest и отдельные unit/property/contract-наборы запрещены, включая косвенный запуск. Не измерять скорость и не использовать предельные планы.

```sh
npm --prefix frontend run build
cd frontend
npx playwright test tests/room-editor.spec.ts tests/project-document.spec.ts tests/project-stages.spec.ts --grep 'context \|deletion \|clear project \|angle tool ' --workers=1 --timeout=15000 --reporter=line
```

Это планируемые префиксы новых test titles. До реализации таких тестов команда не является подтверждением готовности. Общую browser-install команду использовать только если Chromium отсутствует. После успешных новых проверок запускать адресно изменённые старые сценарии пяти существующих файлов; полный повтор не требуется, если нет новых изменений или неразрешённых рисков.

## Фикстуры и адаптация существующих проверок

- Малый план двух соседних прямоугольных комнат с общей стеной, отдельной внешней стеной, граничным узлом, используемым этой стеной, и независимой точкой.
- Комната с внутренним void и отдельным вложенным неотмеченным кольцом; длина цепи и угол на удаляемом участке, released условие и независимое условие.
- Исходная стена из трёх участков для выбора диапазона из двух участков; отдельные версии с fixed/released условием диапазона и общим размером полной цепи; трёхлучевой узел плюс несвязанная стена; отдельный простой разрешимый угол 60°/270°.
- Полный v3 документ: name/address, несколько rooms включая detached, raw конфликтующий ввод, подтверждения, restorePoint, параметры/правила, сохранённый graphV3 либо legacyV2 pending.
- Существующие старые дефектные документы FR-034 остаются без ремонта; никакая fixture не содержит реальные пользовательские данные.

В `fixtures/projects.ts` заменить confirmRoom и другие helpers, использующие селекты, на выбор настоящей внутренней точки комнаты/доступного SVG target. UI тесты preset creation заменить рисованием через инструмент, когда проверяется создание, либо seed маленького документа для подготовки другой проверки. Seed не заменяет действие, которое является предметом теста. Старые API/pending addTemplate проверки сохранить без скрытой кнопки UI.

Для G26 дополнительно сравнить реальные множества segment/vertex/constraint/void IDs, а не только картинку. Удаляемая граница включает hole rings; предусмотреть отдельную короткую проверку. Ошибка независимой комнаты и невыполнимое размерное условие не мешают безопасному удалению соответствующего объекта; повреждённую границу сервер не угадывает.

Для G24r дополнительно проверить маленькими API e2e действующие категории: неверный входной снимок → 422; корректный basis с неверной новой целью range → HTTP 200/invalid с исходным графом; допустимый target с конфликтующим размером → HTTP 200/unresolved с сохранённым условием. Это не отдельный contract suite.

Для G29/G30 не проверять актуальность старых результатов только по наличию текста: попытка экспорта должна быть недоступна до нового явного успешного подбора. SVG/CSV экспортируются синхронно из текущего результата; не добавлять фиктивный export endpoint или await ради теста. JSON проекта после clear экспортирует только текущее пустое содержимое. В G30 задержки управляются promises/interception и освобождаются сразу после нужного действия; без длительных sleeps и измерения времени. G30b контролирует очередь через настоящий Web Lock, не подменяет документ через обход CAS. G30i задерживает только File.text управляемым promise в изолированном контексте; разбор, миграция и preview остаются настоящими. Освободить promise сразу после проверяемого действия, без таймеров ожидания или замеров скорости.

## Связанные регрессии

После адаптации helpers адресно проверить прежние G01–G22: четыре этапа/selected-room guards, независимые комнаты, точные длины и chain ranges, сохранение conflicting fields/pending, v2/legacy migration, invalid JSON, stale placement, grid/zoom invariance и защиту вершин 12 CSS px. Старые UI шаги через «Второй луч», «Сектор» и «Помещение» заменить новым прямым выбором. API addTemplate/legacy pending не удалять из совместимости.

Сборка проверяет новые command unions/schema и JSX. Все геометрические/конкурентные проверки проходят как короткие e2e; дополнительных suite типов не добавлять.
