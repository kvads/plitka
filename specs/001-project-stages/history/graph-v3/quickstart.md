# Quickstart: проверка графового редактора

Это руководство для будущей реализации. В фазе планирования код и тесты не запускались. Результаты прежних 46 e2e относятся только к v2: [историческая запись](history/contour-v2/quickstart.md). Они не подтверждают готовность нового редактора.

## Запуск после реализации

Требуются Python 3.12–3.14, Node.js 20.19+ либо 22.12+, npm и Chromium Playwright. Существующее окружение не пересоздавать. При новой установке из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm --prefix frontend ci
```

В отдельных терминалах из корня:

```sh
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

Открыть http://127.0.0.1:5173/. Проверить список проектов, открыть тестовый проект. `/api/health` должен вернуть JSON, пустое тело не считать успехом. Использовать изолированные браузерные контексты и fixtures, не пользовательские документы.

## Разрешённые проверки

Перед запуском проверить scripts и состав указанных файлов: они должны содержать только быстрые функциональные e2e. Performance, нагрузочные, стресс-тесты, benchmark и pytest запрещены, включая косвенный запуск общим скриптом. Сборка/typecheck разрешены. Один worker, test timeout 15 с, action timeout 5 с; сценарии с несколькими независимыми случаями разделить на короткие тесты.

```sh
npm --prefix frontend run build
cd frontend
npx playwright install chromium
npx playwright test tests/projects.spec.ts tests/planner.spec.ts tests/project-stages.spec.ts tests/room-editor.spec.ts tests/project-document.spec.ts --workers=1 --timeout=15000 --reporter=line
```

Расширять эти существующие файлы новыми сценариями ниже. Серверные ошибки/задержанные ответы разрешено воспроизводить перехватом запроса; положительные проверки геометрии должны обращаться к реальному FastAPI. Не замерять скорость, не генерировать предельные планы для нагрузки, не увеличивать геометрические допуски ради прохождения.

| --- | --- | --- |

| G02 | Соединить произвольные две точки, затем другие; повторить выбор существующей точки; построить стену числовым вводом/клавиатурой | Явная стена между выбранными узлами, нет обязательного порядка; нет дубликата точки или нулевой стены; Escape сбрасывает начало |
| G03 | Присоединить точку к середине стены, пересечь две стены новой линией; отдельно пересечь в существующем узле | T/X-сочленения имеют общие ID; все участки созданы атомарно; повтор запроса не дублирует их; Undo возвращает весь граф |
| G04 | Задать стене 4000 мм, разделить; задать первому участку 1500; разделить его повторно; отдельно ввести конфликт | Сумма исходной цепи 4000, остаток 2500; повторный split сохраняет 1500 на диапазоне; конфликт сохраняет введённое условие, не меняет fixed молча |
| G05 | Два замкнутых помещения и отдельные открытые линии внутри/снаружи; выбрать одно помещение | Расчёт только выбранного; линии не вычитают площадь и не препятствуют готовности независимой комнаты; параметры разных комнат независимы |
| G06 | Добавить узел на стену без разделения комнаты; затем создать перегородку и удалить её | Первое действие сохраняет roomId/настройки, но новые derived требуют согласия; split/merge оставляют старую запись detached, снимают выбор и не наследуют confirmed |
| G07 | Явное отверстие внутри прямоугольника; отдельно вложенное неотмеченное кольцо; импорт v2 с hole | Void не предлагается как комната, вычитается из площади; неотмеченное кольцо даёт отдельную комнату; v2 hole сохраняет роль и площадь |
| G08 | Выбрать пару лучей T-узла и сектор; задать угол; отдельно проверить 270°, свободную стену и прямоугольник | Условие привязано к конкретным лучам; 180° прямой цепи показывается derived; опора свободной стены сохраняется; ручные размеры ≤0,1 мм/° |
| G09 | Построить 4200×3600 и параллелограмм 4000×3000 с 60°/120°; изменить только zoom и размер окна | Площади 15,12 и 10,392305±0,001 м²; при zoom 50/100/200% и 375/1440 px координаты/метрики acceptedPlacement неизменны; время не измеряется |
| G10 | Раздельные fixtures v2: fixed+ack, незамкнутый draft, pending с отличным basis, holes; v3 round-trip | ID/координаты/ввод/условия каждого снимка сохранены; ack не создаётся заново; pending не запускается при reload, повтор и отмена корректны; detached сохраняется |
| G11 | Отказ записи, две вкладки v3, запись старой v2 вкладкой, повреждённый v3 при наличии v2 | Нет ложного «Сохранено» или потери чужих данных; конфликт виден; старый ключ не затирается; нет скрытого fallback |
| G12 | Задержать geometry/layout/optimize и сменить помещение/проект/этап; отдельно пустой/HTML/оборванный JSON | Старый ответ не применяется и не переключает этап; ошибки понятны, черновик остаётся, повтор работает; неудачный сдвиг не экспортируется |
| G13 | Меню/поля поверх полотна, pointer drag/up/click, касание; пройти всё клавиатурой на 375 px | Нет добавления точки сквозь меню/после drag, двойных действий, скрытого фокуса и горизонтальной прокрутки; только панель активного этапа |
| G14 | Ошибка в независимой комнате; затем общее fixed условие/ожидающая правка; вернуть весь план к confirmed | Независимая ошибка не блокирует выбранную; транзитивная зависимость блокирует; неизвестное влияние pending временно закрывает экспорт; восстановление показывает затронутые комнаты и выполняется целиком |

G03/G04/G10–G14 следует разбить на отдельные короткие случаи. Положительные G08/G09 обязаны решаться, unresolved не заменяет успешную проверку простых фигур. Наложения, невалидный void, конфликтный размер и возникшее после move ненодированное пересечение должны давать адресную диагностику и сохранённое намерение.

## Сохранение прежних гарантий

Перенести применимые E01–E15 из [предыдущего руководства](history/contour-v2/quickstart.md), адаптировав действия к явным инструментам, v3 и выбранной комнате. Сохранить проверки: четыре этапа/guards, привязка к узлам и линиям сетки, ручные размеры вне сетки, derived acknowledgment, повреждённый импорт и ревизии, ошибочный inset, accepted/pending placement, SVG/CSV, metadata/viewport без сброса результата. Историческое требование обязательного замыкания всего draft заменено готовностью выбранной области.

При завершении реализации записать фактическую команду/результат и ограничения проверенной среды отдельным разделом. До запуска не помечать G-сценарии пройденными. Модель и контракты: [data-model](data-model.md), [API](contracts/geometry-api.md), [JSON/storage](contracts/project-file.md), [UI](contracts/workflow-ui.md).

Уточнения проверок после анализа U1/I1/I2/C1 (отдельные короткие e2e): G10/G14 — конфликт 4300/4200, изменение другой стены на 4300, reload сохраняет оба условия; отдельная отмена последней правки после reload возвращает 4300/4200. G12 — снять fixed при прежних координатах, подтвердить: прежний результат и поздний ответ недоступны, новый подбор разрешает экспорт. G10 — legacy открывается на объекте без согласия, v2 сохраняет действительные ack/fixed и доступный этап. G08 — 3175,5/3175.5 мм и 60,5/60.5° дают одинаковые сохранённые значения через общий числовой ввод.

В G08/G10 после успешного ответа проверить сохранение raw «3175,5» при числовом значении 3175.5. В G14 проверить исправление конфликта через releaseConstraint и reconcile. Случай отмены второй правки после reload воспроизводить с сохранённым pending (ответ задержан): successful Undo проверяется отдельно в текущей сессии, поскольку история Undo не сериализуется.

## Фактическая проверка реализации v3 — 2026-10-11

Реализованы независимые вершины, явное соединение и T/X-сочленения, сохранение исходной цепи стены и размерных диапазонов, редактор углов/направления, четыре меню на одном полотне, выбор помещения/отверстий, v3 хранение/миграция/восстановление и расчёт выбранной комнаты. Список проектов сохраняет названия и адреса.

Проверенная среда: локальный FastAPI на `127.0.0.1:8000`, Vite на `127.0.0.1:5173`, Chromium Playwright, один worker; action timeout 5 с, test timeout 15 с. Тесты используют изолированное хранилище, реальные успешные ответы FastAPI, подмену только для ошибок и задержек. Пользовательский проект не заменялся тестовыми данными.

Из каталога `frontend`:

```bash
npm run build
npx playwright test tests/projects.spec.ts tests/planner.spec.ts tests/project-stages.spec.ts tests/room-editor.spec.ts tests/project-document.spec.ts --reporter=line
```

- Build/typecheck: успешно.
- Полный запуск пяти разрешённых файлов: **61 passed**.
- После последней правки подтверждения удаления выполнены только затронутые проверки: **3 passed** (новое удаление вершины с условиями + повторные проверки v3 round-trip и повреждённого импорта). Итого в текущем наборе **62 отдельных сценария**, каждый проверен успешно.
- Проверены реальные площади прямоугольника 4200×3600 — 15,12 м² и решённого параллелограмма 4000×3000, 60°/120° — 10,392305 м²; 4000=1500+2500 и повторное деление с сохранением диапазона; конфликт 4300/4200 и его исправление/отмена; независимые ошибки/pending; stale после снятия fixed и Undo.
