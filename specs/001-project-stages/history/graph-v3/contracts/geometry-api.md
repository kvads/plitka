# Geometry API: граф плана v3

Целевой контракт; реализуется после генерации новых задач. FastAPI остаётся stateless. Типы графа и условия определены в [data-model.md](../data-model.md). Старые `/api/geometry/*` сохраняются для точного повторения migrated legacyPending; обычный v3 UI использует новые маршруты.

## Общие правила

JSON UTF-8, только конечные числа, координаты/длины в мм, углы в градусах, площадь в мм². Тело ≤2 МиБ; превышение → 413 JSON. Неизвестные поля, повреждённые ссылки, некорректные типы/лимиты → 422 JSON. Невозможность удовлетворить условия — предметный HTTP 200 с `status=unresolved`, не ошибка формата. Непредвиденный отказ → 500 JSON без внутренних подробностей. Пустой ответ никогда не означает успех.

Общий error: `{error:{code,message,details?}}`; стандартную FastAPI validation error нормализовать в этот envelope. Frontend сначала читает текст, затем проверяет JSON и схему; пустой/HTML/оборванный ответ даёт понятную ошибку без потери ввода. Проверки лимитов см. plan.md. Ни один маршрут не записывает проекты.

## POST /api/plan/validate

Request: `{schemaVersion:3, requestId, draftRevision, basisKey, graph:GraphSnapshot, selectedRoomKey?:string}`.

Response: `{schemaVersion:3, requestId, draftRevision, basisKey, status, graph, faces, measurements, issues}`. `status=valid|invalid|unresolved`; граф возвращается без исправления координат/условий. `faces` содержит FaceCandidate, а не клиентские roomId. Проверяется структура, топология, фактическое выполнение fixed, принадлежность holes и транзитивные зависимости выбранной области. Конечные координаты вне рабочего диапазона и конечные неположительные размеры сохраняются как диагностируемый draft; solve не принимает их как допустимое решение. Некорректная геометрия сохраняема: её диагностика отличается от структурно повреждённого документа.

`Issue={code,message,entityIds,fieldKey?,scope:global|component|room,affectedRoomKeys:[]}`. Для глобального нарушения readiness всех комнат закрыта; component/room ограничивают только доказанную область влияния. Неизвестное влияние ожидающего запроса временно блокирует подтверждение/экспорт. Независимые открытые линии не являются ошибкой замыкания выбранной комнаты.

## POST /api/plan/command

Request: `{schemaVersion:3, commandId, draftRevision, basisKey, graph:GraphSnapshot, command, selectedRoomKey?:string}`. `graph` — неизменяемый basis операции, не частично разделённый preview. Frontend сохраняет basis и полное намерение до запроса.

Command — tagged union по `type`:

| type | Данные и смысл |
| --- | --- |
| addVertex | `point:{x,y}`; независимая вершина; совпавший существующий узел переиспользуется |
| connect | `fromVertexId`, `to:{vertexId}` либо `to:{segmentId,point}`; проекция должна лежать на указанном участке; создаёт стену и все точечные сочленения |
| moveVertex | `vertexId,point`; завершённое перемещение, сохраняющее заданные условия |
| setLength | `constraintId,target:{kind:segment|chain,id,range?},value`; chain range — пара существующих узлов цепи, отсутствие range означает всю стену |
| setAngle | `constraintId,vertexId,firstSegmentId,secondSegmentId,sector:cw|ccw,value` |
| setOrientation | `constraintId,chainId,value`; направление исходной стены |
| releaseConstraint | `constraintId`; снимает конкретное условие |
| deleteElements | `vertexIds,segmentIds,acknowledgedConstraintIds`; удалить только перечисленное и явно показанные зависимости |
| markVoid / unmarkVoid | `boundary:DirectedSegmentRef[]` / `voidId`; явная роль отверстия |
| addTemplate | `shape:rectangle|lShape,origin:{x,y},width,height,notchWidth?,notchHeight?`; положительные размеры, вырез меньше соответствующих сторон; добавляет геометрию через ту же обработку пересечений |
| reconcile | без дополнительных данных; повторить решение текущих условий |

Нечисловая строка сохраняется в fieldInputs клиента и не отправляется как число. Десятичная точка и запятая разбираются общим NumberField: 3175,5/3175.5 и 60,5/60.5 дают равные конечные числа; API получает JSON numbers. Новые ID выводятся детерминированно из commandId и типа/ранга создаваемого объекта; сервер не хранит таблицу повторов. Одинаковые basis/commandId/command дают одинаковые ID и топологический результат. Изменённое намерение получает новый commandId.

Response: `{schemaVersion:3,commandId,draftRevision,basisKey,status:applied|invalid|unresolved,graph,splitMap,addedIds,removedIds,affectedChainIds,faces,measurements,issues}`. `splitMap={oldSegmentId:childSegmentIds[]}` отображает каждый разделённый segmentId в упорядоченные дочерние ID; цепь и узлы доступны по ссылкам возвращённого графа. `applied` означает допустимость операции, но не автоматическое подтверждение размеров пользователем.

Для dimension-команд сервер применяет ввод к полному набору graph.constraints до solve. При invalid/unresolved возвращает прежние координаты/связи basis с обновлёнными constraints, issues относятся ко всему набору и command. Введённые условия хранятся в draft.constraints, а не только в pending; новое изменение другого условия решается совместно со всеми предыдущими. Для структурных команд/move отказ возвращает неизменённый basis, intent остаётся pending до явного retry/cancel. При успехе граф/условия/splitMap/области применяются атомарно, затем очищается pending. Новый запрос не строится на непроверенном частичном split. Повтор не создаёт дубликаты.

## Топология и размеры

Создание стены автоматически делит все пересекаемые участки и новую стену, переиспользуя существующий узел пересечения. Технический epsilon 1e-7 мм относится только к вычисленной топологии. Наложение по отрезку, нулевая/дублированная стена отвергают всю команду. Перемещение и solver не создают скрытые сочленения: возникшее ненодированное пересечение — ошибка операции.

При разделении исходный WallChain сохраняет endpoints, порядок и прямолинейность. Его fixed total остаётся суммой участков; производные длины не становятся fixed. Если ранее вручную измеренный участок делится снова, его constraintId/value сохраняются как chainLength с range между прежними концами участка. Угол переносит ссылку на дочерний луч у той же вершины. Нельзя заменить общий размер независимыми фиксациями всех детей.

Решается транзитивно связанная система геометрии/условий; сохраняются опоры и ориентация свободной стены. Независимая проверка после решения проверяет все fixed ≤0,1 мм/°, порядок, прямолинейность, площадь и пересечения. Ограниченный численный поиск не доказывает несовместимость: exhausted → unresolved. Ручные значения не ослабляются.

`polygonize_full` извлекает ограниченные области. Открытая линия внутри комнаты не вычитает площадь и не получает отдельный зазор; перегородка выделяет новые помещения только после образования замкнутых областей. Явные void исключены из списка комнат. Вложенные неотмеченные кольца дают внутреннюю комнату и внешнюю область с отверстием. Недопустимый компонент, касающийся области, нельзя молча отбросить и объявить область готовой.

## Подтверждение и раскладка

Сервер возвращает канонические outline/holes и dependencyKey/geometryKey/measurementKey для FaceCandidate; канонизация не округляет размеры. Клиент связывает topologyKey с сохранённым roomId, хранит явное подтверждение и проверяет неизменность ключей. Простое коллинеарное разделение цепи сохраняет topologyKey; split/merge комнаты требуют нового выбора.

`/api/layout` и `/api/optimize` и их ответы сохраняются. Адаптер отправляет только подтверждённую выбранную область и её материал/правила: outline 3–100 вершин, ≤20 holes по 3–100, tile 50–2000, grout 0–20, gap 0–100, threshold 1–1000, angle [0,90), offset ±100000. Превышение лимита выбранной области объясняется до запроса. Область после отступа и число ячеек проверяет существующий planner при явном запуске.

Любой ответ применяется только при совпадении projectId, roomId (для раскладки), поколения, ревизии и входного ключа. Abort — дополнительная мера, не замена проверки. Поздний ответ не меняет чужое помещение, этап или сохранённый документ.

Ключ результата включает confirmed dependencyKey с размерными условиями и fixed. Снятие фиксации при прежних координатах инвалидирует результат и поколение запросов; одно повторное подтверждение не разрешает экспорт старого результата.

Dimension-команды — setLength/setAngle/setOrientation/releaseConstraint; reconcile решает текущий набор без изменения условий и имеет тот же режим pending. При актуальном ответе клиент применяет graph с сохранением текущих draft.fieldInputs; текст не восстанавливается из серверного basis. Cancel восстанавливает текст из basis до операции. Геометрические зависимости расширяются fixed-условиями, а dependencyKey содержит также fixed=false условия на уже включённых targets.
