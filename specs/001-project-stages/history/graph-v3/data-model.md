# Data Model: ProjectDocument v3 и граф плана

Целевая модель после FR-030–033; не описание уже работающего v2. Координаты — мм, углы — градусы, API-площади — мм², UI — м². Числа конечны, хранимые координаты не округляются.

## ProjectDocument

| Поле | Тип / правило |
| --- | --- |
| schemaVersion | literal 3 |
| id | UUID нового проекта; при миграции сохраняется прежний непустой ID ≤100 символов |
| name / address | имя после trim 1–120; адрес 0–300 символов |
| documentRevision | целое ≥0, локальная ревизия успешной записи |
| plan | PlanState |
| rooms | RoomRecord[]; уникальные roomId, включая detached записи |
| selectedRoomId | существующий roomId или null |
| workflow | requestedStage: object / tile / rules / variants |
| viewport | centerX, centerY, zoom>0, gridStepMm>0 |

Материал и правила принадлежат RoomRecord. Пока помещение не выбрано, этапы плитки/правил закрыты; новые записи получают текущие исходные значения 600/2/10/100/0. Настройки ранее выбранных комнат не переносятся на новую комнату и не удаляются при потере её границы.

## PlanState и GraphSnapshot

PlanState = `{draft, draftRevision, pendingEdit|null, restorePoint|null}`.

GraphSnapshot = `{vertices[], segments[], chains[], voids[], constraints[], fieldInputs}`.

- Vertex = `{id, x, y}`. Степень вершины может быть 0, 1, 2 или больше. Порядок массива не создаёт связи.
- Segment = `{id, startVertexId, endVertexId, chainId}`. Оба конца существуют в этом снимке; разные ID обязательны. Совпадающие координаты разных концов — геометрическая ошибка нулевой длины, не структурный отказ документа. Направление сохраняется для опор и отображения.
- WallChain = `{id, startVertexId, endVertexId, segmentIds[]}`. Представляет одну исходную прямую стену; участки перечислены от исходного начала к концу и имеют согласованное направление. Каждый Segment принадлежит ровно одной chain. На split изменяется список участков, chainId и исходные концы сохраняются. Коллинеарность и строгое расположение внутренних узлов между концами проверяются геометрически. При повторном split свойства сохраняются.
- Void = `{id, boundary: DirectedSegmentRef[]}`. Явно исключённое замкнутое кольцо. DirectedSegmentRef = `{segmentId, forward:boolean}`. Это отдельная семантика отверстия, а не пометка всех замкнутых контуров. При split ссылки заменяются последовательностью child refs с прежним обходом. Невалидное/открытое кольцо сохраняется как ошибочный draft; чужие ссылки — структурная ошибка.
- fieldInputs = словарь применённого текста по устойчивому пути (`vertex:<id>:x`, `chain:<id>:length`, `segment:<id>:length`, `angle:<constraintId>:value`); строки ≤100. Нечисловой ввод не превращается в 0/NaN. Незавершённый набор до blur/Enter остаётся runtime.

ID непустые ≤100 символов, уникальны среди вершин/участков/цепей/отверстий/условий внутри одного снимка. Равные ID разных снимков draft/confirmed/basis ожидаемы. Все ссылки разрешаются внутри своего снимка. Структура не требует planar/closed/валидных размеров, но требует корректных типов и ссылок.

Пределы: 2100 вершин, 6300 сегментов, 6300 chains, 12600 условий, 20 voids; координаты для вычислений ±100000 мм. Конечные координаты вне диапазона допускаются в сохраняемом draft, но не в решении. Файл/запрос ≤2 МиБ; достигнутый предел показан до применения команды, не скрытое усечение.

### Транзакции связности

`addVertex` не создаёт Segment. `connect` создаёт исходную chain и её участки, собирает все точечные пересечения, переиспользует общие узлы и разделяет старые сегменты. В ответе — `splitMap {oldSegmentId: childSegmentIds[]}`, добавленные/удалённые ID и затронутые chainId. Child ID выводятся детерминированно из commandId и исходных идентификаторов/рангов, не случайного порядка обхода Shapely.

Сохранять provenance требуется для всех стен, даже без ручного замера. Коллинеарное перекрытие, нулевая новая стена или уже существующая связь не выполняют топологическую транзакцию; намерение и диагностика сохраняются. Одна отмена восстанавливает basis со всеми ID и условиями.

Удаление участка/вершины явно перечисляет затронутые chains, углы и общие размеры. Нельзя оставить «общую стену» с разрывом. Разрушенные chains удаляются вместе с явно подтверждёнными связанными условиями; оставшиеся непрерывные части получают новые chains. Нет автоматического объединения соседей узла степени ≥3 или молчаливого переноса фиксации.

## DimensionConstraint

Каждое условие имеет `{id, kind, target, value, fixed}`:

| kind | target | Смысл |
| --- | --- | --- |
| segmentLength | segmentId | положительная длина участка |
| chainLength | chainId | общая длина исходной стены |
| angle | vertexId, firstSegmentId, secondSegmentId, sector: cw/ccw | угол от первого исходящего луча ко второму в выбранном секторе |
| orientation | chainId | направление от начала цепи к концу, modulo 360 |
| legacyUnbound | originalConstraint + reason | только для миграции прежнего условия без допустимой пары лучей; блокирует зависимую область до явного исправления/удаления |

У angle оба участка инцидентны vertexId; луч направлен от этого узла, независимо от направления Segment. value в (0,360), ручное 180 запрещено прежними требованиями, вычисленное 180 разрешено. Тип legacyUnbound не разрешён для новых пользовательских операций и не участвует в численном solve. Неверные конечные числовые значения других видов сохраняются с диагностикой.

На одном target/kind/sector — одно условие; повторный ввод меняет value и fixed=true. fixed=false сохраняет происхождение, но надпись показывает действительное измерение. Допускаются одновременно chainLength и segmentLength; они должны согласоваться. Прямолинейность chain сохраняется независимо от fixed.

При split угловые ссылки переназначаются на ребёнка, продолжающего нужный луч у старой вершины. segmentLength разделяемого участка переносится на общий замер группы его child-участков: для этого target chainLength допускает `range:{startVertexId,endVertexId}` внутри той же chain. Полный chainLength имеет range=null; диапазон должен быть непрерывным и упорядоченным. Значение и ID условия сохраняются. Это необходимо при повторном разбиении уже вручную измеренного участка. Снятие общей фиксации не удаляет chain.

## Измерения и подтверждения

Measurement = `{key, kind, target, value|null, source:entered|derived}`. Для chain, диапазона, segment и угла ключи различны. Угол в узле степени ≥3 не обозначается одним wallId. Для acknowledgment берутся вычисленные размеры границы выбранной комнаты, её voids и общие размеры зависимых цепей; произвольные пары лучей, не относящиеся к границе, не требуют согласия.

Acknowledgment = `{measurementKey, entries:[{key,kind,displayedValue}]}`. Entries отсортированы по key; отображаемая точность 0,1, ключ включает точный dependencyKey. Смена координат даже в пределах округления требует новой проверки; metadata/viewport — нет. Новое деление участка меняет набор измерений и требует согласия для новых derived-значений, не меняя roomId.

## Производные помещения и RoomRecord

FaceCandidate = `{topologyKey, outer:DirectedSegmentRef[], holes:DirectedSegmentRef[][], polygon, areaMm2, dependencyIds, dependencyKey, geometryKey, measurementKey, validation}`. Получается из планарных стен; не сериализуется как источник истины. Висячие стены/отдельные точки не превращаются в границы автоматически.

Планаризация не выполняется на чтении. Для graph без ошибок использовать polygonize_full. При наличии проблем выделить ошибочные компоненты/сегменты, получать кандидаты из корректной части только для диагностики; кандидат блокируется, если дефект/его область влияния касается его Polygon. Отбрасывание дефектного сегмента не должно сделать затронутую комнату «готовой».

Void-кольца участвуют в извлечении границ, но Polygon, лежащие внутри явно отмеченного void, не выдаются как комнаты. Void обязан находиться строго внутри внешней границы владельца и не касаться другого void; плохой void не игнорируется. Неотмеченный вложенный замкнутый контур даёт отдельную внутреннюю комнату и внутреннее кольцо окружающей области.

RoomRecord = `{id, topologyKey|null, binding:attached|detached, name, material, rules, fieldInputs, acknowledgment|null, confirmed|null}`. `material={tile,grout}`, `rules={gap,threshold,angle}`. Пустая/некорректная старая комната мигрирует в detached запись с исходными настройками, не исчезает.

TopologyKey: канонический циклический обход направленных chainId; последовательные участки одной цепи сворачиваются, в том числе на стыке конца/начала цикла; внутренние кольца сортируются. Координаты не входят. Координаты и новые измерения входят в другой ключ. При единственном точном совпадении привязать существующий roomId. При split/merge сохранить старую запись detached, снять её selection, создать новые неподтверждённые записи. Никакого наследования по центроиду/площади. Если во время проверки ключ неоднозначен, не выбирать автоматически.

ConfirmedRoom = `{graph, boundary, topologyKey, dependencyKey, geometryKey, measurementKey, acknowledgment, sourceDraftRevision}`. graph — независимая глубокая копия транзитивно замкнутой части графа зависимостей (все ссылки локальны); boundary — замкнутые outer/holes refs этого снимка. Координаты для LayoutRequest извлекаются только отсюда. После загрузки ключи пересчитываются, строкам из файла не доверяют.

## Зависимости и guards

От границы/voids включить её вершины/сегменты, содержащие их цепи и инцидентные фиксированные условия, затем их targets до неподвижной точки. Геометрические дефекты, пересекающие область, также включены. Backend возвращает для каждой Issue `affectedRoomKeys[]` и `scope:global|component|room`.

- `roomReady`: selectedRoomId связан с текущим FaceCandidate, область valid, относящиеся pending/fieldInputs отсутствуют, computed dependencyKey соответствует confirmed, acknowledgment соответствует актуальному набору. Общая draftRevision сама по себе не определяет готовность всех комнат.
- `materialReady`: tile 50–2000, grout 0–20, нет ошибок текста выбранной записи.
- `rulesReady`: gap 0–100, threshold 1–1000, angle ≥0 и <90; нет ошибок текста. Расчёт области после gap и лимит 1600 ячеек остаются задачей явного optimize/layout.
- Независимые открытые участки вне комнаты не блокируют. Общие стены/узлы и связанные условия блокируют все зависимые комнаты. До свежей проверки неизвестного влияния новой правки экспорт временно запрещён.

## Pending, история и отказ от изменений

Полный введённый набор условий хранится в `draft.constraints`, применённый текст — в `draft.fieldInputs`, независимо от pending. Dimension-команда сначала обновляет только своё условие в draft, сохраняя остальные; координаты до успешного solve остаются последними принятыми. Некорректный числовой набор допустим в draft. Нечисловой текст не подменяет последнее числовое значение и блокирует зависимую готовность.

PendingEdit — discriminated union:

- `graphV3`: `{kind, commandId, command, basisGraph, targetDraftRevision}`. basisGraph — полный снимок до текущего действия, включая все ранее введённые конфликтующие условия. Сохранить draft и намерение до вызова сервера; preview положения/связей остаётся runtime, сохраняемая геометрия не меняется до успеха. Актуальный успешный ответ атомарно заменяет граф и очищает pending; отказ сохраняет весь draft.constraints и прежние координаты. Повтор использует тот же commandId/basis. Следующая dimension-команда получает новый ID и basis из текущего draft со всеми условиями; предыдущий ответ инвалидируется поколением, его pending заменяется, но условия не теряются. Пока ожидает/не выполнена структурная команда либо move, новое действие с геометрией блокируется до явного retry/cancel. LegacyPending также нельзя молча заменить.
- `legacyV2`: `{kind, legacyOperation, legacyBasisGeometry, legacyDraftGeometry, targetDraftRevision}`. Только миграция; позволяет точное повторение прежней операции через v2 endpoint и преобразование ответа, без автоматического запуска при загрузке. Нечисловой ввод и выбранное помещение остаются заблокированы по зависимости до результата или отмены.

Undo хранит минимум 20 полных состояний графа, bindings/selection, условий и подтверждений только в памяти. Отмена сохранённого pending после reload восстанавливает его basis; новые draftRevision всегда возрастают, nested targetDraftRevision обновляется.

`restorePoint={graph, bindings:[{roomId,topologyKey}], selectedRoomId}` — копия всего плана при последнем явном подтверждении помещения. Команда «Вернуть план к последнему подтверждению» показывает, что затронет весь план/соседние комнаты, а не только текущую; после применения пересчитывает все bindings/guards. Если restorePoint отсутствует, отдельное явное «Очистить план» с подтверждением. Не восстанавливать только boundary одной комнаты поверх общего графа. RoomRecord с параметрами не удалять. Для v2 restorePoint берётся из converted confirmed, если он был.

## Результаты и переходы

`inputKey` включает roomId, канонические confirmed outline/holes, confirmed dependencyKey (включая kind/target/value/fixed всех зависимых условий), material/rules. Изменение зависимого условия немедленно помечает ResultSet устаревшим и увеличивает поколение запросов, даже если координаты не изменились. Флаг устаревания сбрасывает только новый успешный подбор; повторное подтверждение или возврат прежнего ключа сами по себе результат не оживляют. `ResultSet={roomId,inputKey,token,variants,selectedVariantId,acceptedPlacement,pendingPlacement,locked,stale:boolean}` — runtime. Token содержит projectId, roomId, operationId, inputKey и монотонное поколение запроса. Geometry token содержит projectId, commandId/requestId, draftRevision и basisKey. Abort не заменяет проверку токена.

Commit геометрии сохраняет намерение и ставит проверку; независимость от выбранной комнаты подтверждается ответом. Смена комнаты отменяет ожидаемые запросы и не переносит чужой result. Изменение выбранных material/rules сразу инвалидирует её результаты, без автоподбора. Навигация назад отменяет автопереход ожидающего optimize; принятый актуальный result остаётся в памяти. Ошибка shift оставляет accepted отдельно от pending, экспорт запрещён до успеха или отмены. Reload/import не восстанавливает варианты: variants → rules только при готовых выбранных входах, иначе первый доступный этап.

При неизвестной области влияния правки использовать runtime exportSuspended отдельно от stale. Ответ validate с неизменным dependencyKey снимает только exportSuspended; известное изменение зависимых условий устанавливает stale до нового optimize. Undo в памяти восстанавливает геометрию/условия, но не снимает уже установленный stale результата. После reload варианты отсутствуют.

Dimension-команды: setLength, setAngle, setOrientation, releaseConstraint. reconcile повторяет решение полного текущего набора без изменения условий; его pending имеет те же правила повторения/замены, что dimension. При применении актуального ответа graph объединяется с текущими draft.fieldInputs: серверный снимок не откатывает применённый текст, включая запятую и текст ошибок. После отмены используется fieldInputs из basis.

Fixed-условия расширяют геометрическую зависимость до неподвижной точки; dependencyKey дополнительно включает все сохранённые условия на вошедших targets, включая fixed=false. Поэтому снятие фиксации меняет ключ даже при прежней форме. Размерный ввод на прежнем target заменяет только его условие; другие условия сохраняются.
