# Quickstart: «План» и «Варианты»

Дата: 2026-10-12. Реализация и приёмка завершены: 30 новых быстрых e2e + 13 адресных регрессий, TypeScript/Vite build. На этапе планирования запусков не было; ниже добавлена фактическая приёмка реализации. Прежняя приёмка сохранена в [истории](history/project-deletion/quickstart.md) и не подтверждает новый flow.

## Среда и команды для реализации

Использовать существующие .venv и node_modules без обновления зависимостей. Если серверы уже работают, переиспользовать их. Иначе в двух терминалах из корня проекта:

```bash
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
npm --prefix frontend run dev
```

После реализации сценариев из `frontend/`:

```bash
npx playwright test tests/project-stages.spec.ts tests/project-document.spec.ts tests/projects.spec.ts --grep 'room flow ' --workers=1 --timeout=15000 --reporter=line
npm run build
```

Общий префикс `room flow ` обязателен для новых тестов во всех трёх файлах. Action timeout 5 с, test timeout 15 с; не повышать лимиты для прохождения. Каждая группа ниже разбивается на короткие самостоятельные сценарии. Только малые планы и реальные ответы backend геометрии/расчёта; управляемая задержка/ошибка допустима для проверки гонок. Performance/load/stress/benchmark, pytest и отдельные unit/property/contract suites не запускать.

Каждый тест — отдельный browser context и искусственные проекты, без чтения/изменения пользовательского каталога. Для гонок вкладок — две pages одного тестового context. Адаптировать существующие confirmRoom/toRules helpers к новому взаимодействию; не оставлять невидимые кнопки старого flow ради тестов. Адресные регрессии старых сценариев запускать только для затронутых зависимостей.

На этапе plan: исходники изучены, документы согласованы; тестов 0, сборок 0. При реализации сюда записать точные команды, число прошедших проверок и обнаруженные ограничения. Завершённые T047–T201 остаются историей; задачи T202–T239 выполнены, фактическая приёмка приведена ниже.


## Последовательность адресной приёмки после уточнений

US1 проверять только после удаления зависимости от confirmed во всех guards результата и экспорта, а не только ready/request. К этому моменту normalizer старых пустых имён уже работает. F01/F08 должны завершаться без ожидания реализации US2/US5.

F09 разделить на короткие тесты: готовый результат → смена страницы → тот же результат/экспорт; optimize success/error во время просмотра «Плана»; ручной layout success/error во время просмотра «Плана»; возврат до ответа с видимым ожиданием. Проверять отсутствие принудительной навигации и повторного запроса, а также сохранение accepted/pending/locked. Отдельно смена комнаты/данных и выход из проекта должны по-прежнему отсекать ответ.

F12 для FR-022 разбить на альтернативы/метрики, деталь, сдвиг, закрепление и SVG/CSV, с использованием короткого существующего сценария там, где он уже покрывает нужное действие. Все новые проверки включать в `room flow `; общий performance-набор не запускать.
