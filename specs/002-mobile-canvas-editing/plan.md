# Implementation Plan: Мобильное полотно и стены с толщиной

**Branch**: `002-mobile-canvas-editing` | **Date**: 2026-10-15 | **Spec**: [spec.md](spec.md)

**Input**: уточнения от 2026-10-15 к существующему мобильному редактору. Единая левая панель и подтверждение вершин уже реализованы; эта итерация исправляет перемещение вида, убирает текст привязки и вводит физические стены.

## Summary

Сделать однопальцевое перемещение инструментом «Переместить полотно» непрерывным во время жеста и сохранять вид один раз после завершения. Удалить текстовые названия привязки с полотна, сохранив маркер и предупреждение о запрете точки. Добавить инструмент «Стена»: проведение линии создаёт стену толщиной 100 мм по умолчанию, с возможностью настроить толщину до рисования и после создания. Линия является осью; стены становятся заполненными областями, автоматически образуют подрезанные стыки у первой встреченной стены и влияют на полезную площадь помещений и расчёт плитки. Новая модель документа удаляет проекты прежних версий при первом открытии в каждом браузере, как прямо выбрал пользователь.

## Technical Context

**Language/Version**: TypeScript ~5.9.3, React ^19.2.0; Python 3.14, FastAPI, Pydantic, Shapely; существующий SVG редактор.

**Primary Dependencies**: текущие React, Pointer Events, SVG, lucide-react и Shapely; новых пакетов не требуется. `backend/geometry/faces.py` уже строит области по осевым линиям, `frontend/src/domain/plan/*` хранит граф и проект.

**Storage**: новый каталог `plitka-projects-v4` и документ `schemaVersion: 4`; запросы/ответы графа получают `schemaVersion: 4`, потому что прежний контракт не содержит обязательной толщины. Клиентский парсер, все вызовы и проверка ответов API, сохранение и сервер переключаются на v4 одним интегрированным этапом после независимых исправлений `pan` и подписи привязки; промежуточное переключение только сервера не считается готовым результатом. Толщина обязательна у каждой цепи стены, включая графы в черновике, подтверждённой комнате, ожидающей правке и точке восстановления. При первом открытии v4 записывается пустой каталог, после чего известные ключи v1–v3 удаляются. Серверной БД проектов нет. Старая JSON-модель не импортируется обратно.

**Testing**: `backend/tests` для построения физических контуров, стыков и команд; Playwright для касаний, мыши, выбранной раскладки, UI стен, удаления старого каталога и сохранения нового; `npm --prefix frontend run build`. Зафиксированные ранее не относящиеся к функции падения остаются базой сравнения, новые регрессии не допускаются.

**Target Platform**: сенсорные браузеры от 320 px, портретная и альбомная ориентации; настольный браузер с мышью и клавиатурой. Существующая боковая панель и диапазон масштаба 0,2–8 сохраняются.

**Project Type**: существующее веб приложение React + FastAPI.

**Performance Goals**: вид следует за каждым кадром движения указателя без скачка на отпускании; один завершённый жест создаёт не более одной записи вида в документе. Предпросмотр стены движется без ожидания серверного запроса на каждом кадре; сервер остаётся источником окончательной геометрии.

**Constraints**: оси и условия размеров сохраняют миллиметровые координаты; физическая стена занимает по половине толщины с каждой стороны оси. В Т-стыке ось новой стены доходит до оси существующей для топологии, но предпросмотр показывает только добавленный вклад: полосу до первого препятствия за вычетом уже занятой области, заканчивающуюся на первой грани без зазора. После сохранения объединённая область полных полос не зависит от порядка создания стен и считает стык один раз; вклад предпросмотра не сохраняется отдельно. Пустой или многокомпонентный полезный контур передаётся как `polygon: null` и `areaMm2: null` с причиной невалидности; пригодный единый контур вне лимитов планировщика сохраняется, но не рассчитывается. Изменение толщины не должно менять идентичность комнаты из-за одного лишь смещения внутренней грани. Импорт старого документа не должен возвращать удалённую модель. Удаление касается только известных ключей проектов этого приложения в браузере, без очистки иных данных источника.

**Scale/Scope**: один активный проект, до существующих лимитов графа и планировщика. Затронуты фронтенд, схема документа, API графа и построение полезного контура; сам алгоритм подбора плитки получает новый контур без изменения его эвристики. Существующие инструменты вершин и соединения остаются доступными; создание или изменение ими стены также должно присваивать/сохранять толщину. PostgreSQL и межпользовательское хранение не входят в объём.

### Последовательность последующей реализации

1. Исправить однопальцевый `pan` на временный вид, обновляемый в каждом кадре по экранному сдвигу от начальной точки; на отпускании сохранить итог один раз. `pan` никогда не вызывает сдвиг раскладки. Удалить текстовые типы привязки, сохранив предупреждение о запрете точки. Эти два изменения проверяются самостоятельно на существующем формате.
2. Затем единым интегрированным этапом ввести v4 типы и строгую проверку толщины без автоматического присвоения старым документам, перевести все вызывающие и проверяющие API модули (`api.ts`, `deletion-api.ts`), меню проекта и привязку комнат, сервер, создание/сохранение/удаление, все вложенные снимки и тестовые фикстуры. Реализовать однократную очистку v1–v3 и запрет старого импорта. До завершения этапа приложение не считается готовым к выпуску.
3. Добавить толщину в `WallChain` на клиенте и сервере, команды создания/изменения стены и перенос толщины при split, delete, Undo и восстановлении. Значение по умолчанию 100 мм; недопустимый ввод не меняет проект. Допустимое изменение толщины, уничтожившее полезный контур, возвращает `status: applied` и сохраняет новый граф с невалидным помещением; отказ команды возвращает `status: invalid` и прежний граф. Прямо проверить оба ответа, повтор команды и конфликт ревизии для `setWallThickness`.
4. Получать области стен из осевых линий и толщины с митровыми стыками и плоскими свободными концами. На первом препятствии обрезать видимую добавленную область у грани, довести осевую связь до оси существующей стены для стыка и не строить видимое продолжение за ним. Объединять площади без двойного счёта; невозможный стык явно отклонять.
5. Вычислять полезный контур как область осевого помещения за вычетом физических стен. Сохранять осевой контур для идентичности комнаты и размерных условий. Включить толщину и полезный контур в ключи актуальности раскладки; пустые/разорванные области передавать с `polygon: null`, `areaMm2: null` и причиной, не отправляя в подбор плитки.
6. Добавить инструмент «Стена», настройку толщины до рисования и у выбранной стены, заполненную SVG-область с различимыми гранями, локальный предпросмотр и доступные ошибки.
7. Проверить геометрию прямой, угла, Т-стыка, узкого помещения и первого препятствия; UI на 320/375/430 px, мышь/клавиатуру, повторный запуск v4 и отказ старого импорта. Сопоставить серверный контур, нарисованные грани и вход алгоритма плитки.

## Complexity Tracking

| Решение | Обоснование |
| --- | --- |
| Новая версия документа вместо миграции | Пользователь прямо выбрал удаление всех старых проектов; отдельный дискриминатор защищает новый пустой проект. |
