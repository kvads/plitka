# Contract: площади и показатели раскладки

Существующие `POST /api/layout` и `POST /api/optimize` сохраняют прежний ответ с площадями в м² для уже открытых старых вкладок. Обновлённый редактор обращается к `POST /api/v5/layout` и `POST /api/v5/optimize`: эти маршруты возвращают площади в мм² и предметные числовые значения с шагом 0,1. Имена полей внутри ответа остаются прежними, а версия маршрута однозначно задаёт их единицы. Запрос использует миллиметры для координат и длин, градусы для угла; v5 отклоняет предметные входные числа вне шага 0,1 с HTTP 422, а старые маршруты сохраняют прежнее правило приёма.

| Поля ответа | Единица после обновления | Правило |
| --- | --- | --- |
| `parts[].area`, `metrics.room_area`, `metrics.laying_area`, `metrics.covered_area`, `metrics.grout_area`, `metrics.waste_area` | мм² | Сервер возвращает площадь с шагом 0,1 мм²; клиент и CSV показывают то же число и единицу без деления на 1 000 000. Если площадь выводится в SVG, её единица также мм². |
| `parts[].width`, `parts[].height`, `parts[].min_width`, `metrics.min_width`, `metrics.symmetry`, `offset_x`, `offset_y`, координаты `parts[].rings`, `parts[].center`, `region` | мм | Шаг 0,1 мм; `symmetry` может быть `null`. |
| `angle` | градусы | Шаг 0,1°. |
| `metrics.waste_percent` | % | Шаг 0,1 %. |
| `metrics.tiles`, `metrics.full`, `metrics.cut`, `metrics.fragments`, `metrics.warnings`, `parts[].source`, `evaluated`, `pareto_count` | счётчики | Остаются целыми. |

Для геометрии новой версии сначала формируются канонические возвращаемые контуры помещения, области укладки и частей с координатами шага 0,1 мм. Канонизация общей границы выполняется согласованно, чтобы соседние части и область не разошлись из-за независимого округления. Затем проверяются топология области, положительная площадь каждой части, число фрагментов, принадлежность частей канонической области и отсутствие наложений с положительной площадью. Число плиток и фрагментов определяется по принятым частям; площади частей, объединения частей, области, швов и отходов вычисляются из этой канонической геометрии с последним округлением до 0,1 мм². Разность отдельно округлённых площадей частей и округлённой площади их объединения может составлять только суммарную погрешность округления; отрицательные швы или отходы и геометрически противоречивые значения недопустимы. Положительные контуры нельзя молча исключать старым порогом `EPS`: если любая положительная площадь контура или расчётного показателя стала бы `0,0 мм²` после округления, вариант непригоден целиком; сохранённая ненулевая площадь никогда не выдаётся как ноль.

Типы нового клиента, оба экрана вызова расчёта, таблицы вариантов, карточка помещения и экспорт используют этот контракт как единый источник единиц. `api.ts` проверяет `v5/optimize` как объект с массивом `variants`, а `v5/layout` — как одиночную раскладку. Старые маршруты продолжают возвращать прежние единицы, точность и правила выбора и не используются новым клиентом. Поскольку проекты прежних версий удаляются, сохранённые ответы в м² не переносятся. Новые сохранённые ответы валидируются по шагу 0,1 в указанных единицах.

В новой версии, если округление обнуляет фрагмент, делает контур самопересекающимся, меняет число частей, выводит часть за область или создаёт наложение с другим фрагментом, `POST /api/v5/layout` отклоняет вариант с HTTP 422 и текстовой причиной в `detail`, без частичного результата. То же правило действует для положительной площади менее 0,05 мм², если выбранное правило округления превратило бы её в ноль. `POST /api/v5/optimize` сначала переводит смещения в целые тики по 0,1 мм и применяет неотрицательный остаток по целому периоду `(tile + grout) × 10` тиков: нуль, полный период и отрицательные эквивалентные смещения дают один ключ. Ключ используется для вычисления, проверки, дедупликации, ранжирования и возвращаемого смещения. Каждый уникальный вариант проверяется до отбора начальных кандидатов, фронта Парето и окончательных вариантов. Непригодные варианты не участвуют в этих наборах; поиск продолжает работу, а если пригодных вариантов нет, возвращает HTTP 422 с причиной в `detail`. `evaluated` считает пригодные уникальные варианты, `pareto_count` — пригодный фронт. Проверка включает малую сохранённую ненулевую площадь (например, 0,1 мм²) и площадь, которая округлилась бы в ноль. Версия геометрического API `/api/plan/command` остаётся v4.

Сравнение версий выполняется для одной прямой раскладки комнаты площадью не менее 1 м² с одинаковыми входом и смещением, кратным 0,1 мм. Старая открытая вкладка показывает и экспортирует м², новая — мм²; после перевода `metrics.room_area` старой вкладки в мм² разница не больше `max(100 мм², 0,001 × старая площадь комнаты в мм²)`. Результаты независимой оптимизации не обязаны совпадать. После перезагрузки прежняя вкладка загружает новый клиент и её следующий расчёт использует v5 и мм².
