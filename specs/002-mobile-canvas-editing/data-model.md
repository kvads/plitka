# Data Model: Мобильное полотно и стены с толщиной

## Сохраняемые данные

### Каталог проектов v4

| Поле | Тип | Правило |
| --- | --- | --- |
| `schemaVersion` | `4` | отличает каталог от v1–v3 даже при пустом списке |
| `projects` | `ProjectDocumentV4[]` | уникальные ID проектов; сохраняется под `plitka-projects-v4` |

При первом входе под блокировкой записи создаётся пустой v4 каталог, затем удаляются только известные ключи проектов v1–v3. Если очистка прервана, следующий вход повторяет удаление остаточных ключей, не меняя каталог v4. Ни один старый проект, включая пустой, не переносится. Разные браузеры очищаются независимо. Новый пустой проект имеет `schemaVersion: 4` и сохраняется при повторных входах.

### Документ проекта (`ProjectDocumentV4`)

Существующие ID, имя, адрес, ревизия, комнаты, выбранная комната, этап, `viewport` и история правок сохраняют смысл. `schemaVersion` становится `4`; все вложенные `GraphSnapshot` используют обязательную толщину стен: основной черновик, basis ожидающей команды, точка восстановления, подтверждённые снимки комнат. Строгий парсер отклоняет v1–v3 и граф без толщины; чтение старого файла из списка проектов не возвращает удалённые данные.

### Граф и стена

| Сущность/поле | Тип | Правило |
| --- | --- | --- |
| `Vertex` | `{id, x, y}` | осевые координаты в мм; существующая уникальность и ограничения |
| `Segment` | `{id, startVertexId, endVertexId, chainId}` | топологическая часть стены; при стыке может делиться |
| `WallChain.thicknessMm` | положительное конечное число, мм | обязательное; 100 мм для новой стены до изменения настройки; одинаково для всех её сегментов |
| `WallChain` | ID, концы, упорядоченные `segmentIds`, толщина | редактируемая физическая стена; разбиение сегмента сохраняет цепь и её толщину |
| `DimensionConstraint` | существующие условия | длины и углы относятся к осевым линиям, не к внутренним граням |

Изменение толщины выбранной цепи не меняет осевые координаты и её ID. При каскадном удалении и разделении выжившие фрагменты сохраняют прежнюю толщину. При Undo/восстановлении возвращается соответствующий снимок со своей толщиной. Недопустимое значение не изменяет сохранённый граф.

### Производная физическая геометрия

| Сущность/поле | Источник | Использование |
| --- | --- | --- |
| `wallArea` | объединение областей всех цепей, по половине толщины с каждой стороны оси | заполненный SVG, единая занятая область без двойного подсчёта стыков, поиск первого препятствия |
| `axisPolygon` комнаты | замкнутые осевые линии | топологическая идентичность комнаты, ссылки и размерные условия |
| `polygon` комнаты | `axisPolygon` за вычетом `wallArea`; `null`, если результат пуст или распался на части | единый полезный контур для площади и алгоритма плитки; `null` блокирует расчёт |
| `areaMm2` | площадь полезного `polygon`; `null` вместе с отсутствующим контуром | показываемая площадь только для пригодного контура |
| `dependencyKey` | зависимые оси, условия и толщина цепей | устаревание подтверждённого снимка при изменении толщины |
| `geometryKey` | полезный контур | актуальность рассчитанной раскладки |

Углы связанных стен соединяются митром, свободные концы плоские. У Т-стыка осевая связь новой стены доходит до оси существующей для топологии. Для предпросмотра её видимый вклад получают как физическую полосу новой стены до первого препятствия за вычетом уже занятой области; поэтому он заканчивается ровно на первой грани без зазора и не показывает скрытый осевой отрезок внутри существующей стены. После сохранения `wallArea` является объединением полных физических областей цепей: итоговая область не зависит от порядка создания стен и не удваивает площадь стыка. Отдельный «видимый вклад» нужен лишь для предпросмотра и не сохраняется как самостоятельный полигон цепи. Если разность осевой комнаты и `wallArea` пуста либо распалась на части, `polygon` и `areaMm2` равны `null`, `validation.valid` равно `false`, а причина содержится в `issues`; нельзя выбирать один компонент молча. Если пригодный единый контур нарушает лимиты планировщика, он остаётся в ответе, но получает невалидный статус и не поступает в расчёт плитки. Изменение толщины не меняет `topologyKey` комнаты само по себе.

### Вид плана (`viewport`)

`centerX`, `centerY` и `zoom` задают вид; `gridStepMm` остаётся внутренним сохранённым шагом привязки. Масштаб ограничен 0,2–8. Временное смещение во время одного жеста `pan` не меняет документ, пока жест не завершён; итог сохраняется один раз. Жест не меняет граф и сдвиг рассчитанной раскладки.

## Временные состояния интерфейса

- `sidebarOpen` остаётся локальным состоянием и не входит в документ: на сенсорном устройстве по умолчанию закрыто, с мышью открыто.
- `panGesture`: ID указателя, начальные экранные координаты, начальный `viewport`, временный вид и активность. Движение вычисляется от исходной позиции в экранных пикселях; `pointerup` завершает одну запись вида, `pointercancel` отменяет временный сдвиг.
- `activeTouches`, `pinchStart`, `suppressSingleTouch`: прежний двухпальцевый жест имеет приоритет и не завершает прерванную одиночную команду.
- `wallToolThicknessMm`: текущее положительное значение инструмента, первоначально 100 мм; изменение влияет на следующие стены в открытом редакторе и не переписывает созданные.
- `wallPreview`: начальная/текущая осевая точка, предложенная толщина, первый контакт с существующей физической областью, допустимый заполненный контур либо причина отказа. Не сохраняется до успешной команды `drawWall`.
- Предпросмотр добавления/перемещения вершины остаётся временным и подтверждается отдельно. Текст типа привязки (`Узел`, `Линия`, `Свободно`) не показывается; маркер и предупреждение о запрете точки остаются.

## Переходы и инварианты

1. `wall idle → dragging → preview → applied/rejected`: перетаскивание строит локальный предпросмотр; отпускание отправляет одну атомарную команду. Успех сохраняет ось, толщину и стык; отказ оставляет прежний граф и показывает ошибку. Смена инструмента, второй палец, `Escape` и потеря касания очищают предпросмотр.
2. `pan idle → dragging → committed/cancelled`: движение меняет только временный вид, завершение сохраняет один итоговый `viewport`. Даже при выбранной раскладке `pan` не вызывает `onShift`.
3. `setWallThickness`: успешная команда возвращает `status: applied`, меняет толщину одной цепи, пересчитывает `wallArea` и затронутые полезные контуры, делает прежнюю раскладку этих комнат неактуальной; даже при исчезновении пригодного контура сохраняет новый черновик с невалидной комнатой и причиной. `status: invalid` означает отказ команды и оставляет документ прежним.
4. Новые команды и ответы графа используют `schemaVersion: 4`; старые запросы отклоняются явно. Ключи идемпотентности/ревизии текущего API сохраняют прежний смысл.
