# Плитка

Планировщик укладки квадратного керамогранита. Python FastAPI + Shapely, React + TypeScript + SVG.

## Docker: локальная разработка

Нужны Docker Engine и Docker Compose v2 или новее.

```sh
cp .env.example .env
docker compose up --build -d --wait
```

Открыть http://localhost:5173. Поднимаются Vite с обновлением интерфейса при изменениях, FastAPI с автоперезагрузкой и PostgreSQL 17. API доступен на http://localhost:8000/docs, база — на `localhost:5432`. Порты и реквизиты локальной базы меняются в `.env`. После изменения зависимостей пересоберите контейнеры этой же командой.

Данные PostgreSQL сохраняются в именованном томе. `docker compose down` останавливает окружение и сохраняет данные; `docker compose down -v` **удаляет данные локальной базы**. Переменные `POSTGRES_*` создают пользователя и базу только при первом запуске с пустым томом; изменение пароля в `.env` не меняет пароль в существующей базе.

Можно поднять только PostgreSQL (`docker compose up -d db`), а приложение запустить на хосте по инструкции ниже. Для проверки подключения сервером задайте `PGHOST=127.0.0.1`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` с реквизитами из `.env`.

## Docker: production

Используется отдельный Compose-файл: единый образ содержит собранный интерфейс и FastAPI, запускается от непривилегированного пользователя. PostgreSQL должен уже работать в общей Docker-сети на том же Docker Engine. Заранее создайте в нём базу и пользователя приложения.

```sh
cp .env.production.example .env.production
# Заполните POSTGRES_NETWORK, PGHOST, PGDATABASE, PGUSER и PGPASSWORD.
docker compose --env-file .env.production -f compose.production.yaml up --build -d --wait
```

`POSTGRES_NETWORK` — имя существующей сети, к которой подключён контейнер PostgreSQL. `PGHOST` — имя контейнера или его alias в этой сети, `PGPORT` — внутренний порт PostgreSQL (обычно 5432), а не опубликованный порт хоста. Production-конфигурация не создаёт контейнер БД, сеть, пользователя или схему. Не объединяйте её с локальным `compose.yaml`.

Приложение доступно на http://localhost:8080. По умолчанию порт опубликован только на loopback для reverse proxy на хосте; `APP_BIND` и `APP_PORT` настраиваются. Reverse proxy в той же Docker-сети может обращаться к `app:8000`. Файлы `.env` и `.env.production` не входят в образ и исключены из Git. Пароли с `$` в env-файлах заключайте в одинарные кавычки.

`/api/health` проверяет процесс, `/api/ready` дополнительно выполняет `SELECT 1` в настроенной базе и возвращает 503 при ошибке подключения. Docker использует `/api/ready` для healthcheck. При временной недоступности внешней базы проверка повторяется и восстанавливается после её возвращения. Без `PGHOST` сервер работает без базы, readiness возвращает `database: not_configured`.

**Хранение проектов пока остаётся в localStorage браузера.** Здесь подготовлены инфраструктура и проверка подключения PostgreSQL; таблицы и перенос проектов в БД ещё не реализованы. Новый адрес или порт приложения использует отдельное хранилище браузера. Авторизации в приложении пока нет.

Проверки внутри контейнера:

```sh
docker compose run --rm backend python -m pytest backend/tests -q
docker compose logs -f backend
```

## Запуск без Docker

Требования: Python 3.12+ (Docker использует 3.14), Node.js 20.19+ или 22.12+, npm.

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm --prefix frontend ci
```

Если в Python отсутствует ensurepip, окружение можно заполнить через `uv pip install --python .venv/bin/python -r backend/requirements.txt`.

В двух терминалах из корня проекта:

```sh
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

Открыть http://localhost:5173. Vite перенаправляет `/api` в FastAPI. Документация API: http://localhost:8000/docs.

Для запуска собранного приложения одним сервером:

```sh
npm --prefix frontend run build
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

После сборки перезапустите FastAPI и откройте http://localhost:8000.

## Возможности

- Главная страница со списком проектов: название, адрес, создание и редактирование карточки. У каждого проекта отдельная раскладка. Старый сохранённый план автоматически переносится в «Мой первый проект».

- Прямоугольник, Г-образная комната, рисование контура по точкам с привязкой 50 мм.
- Точные координаты вершин, добавление и удаление отверстий. Все размеры в мм.
- Сторона плитки, шов, отступ от стен и отверстий, угол сетки, порог ширины.
- Поиск по сдвигам с уточнением и выбором недоминируемых альтернатив.
- Ручной сдвиг мышью либо числовыми полями, закрепление выбранной раскладки.
- Масштаб, внешний вид и проверка, выбор детали, таблица с размерами.
- Сохранение в localStorage, переносимый JSON-проект, SVG-план с номерами и габаритами подрезок, CSV-ведомость.

## Алгоритм и ограничения

Геометрия проверяется до расчёта. Отрицательный буфер формирует отступ вдоль всех границ. Помещение вращается в систему координат сетки, затем пересекается с квадратами со стороной `tile` и периодом `tile + grout`. Геометрия возвращается в координаты комнаты, включая внутренние кольца и отдельные фрагменты одной ячейки.

Поиск фиксирует заданный угол. Проверяет сетку сдвигов 8×8, положения относительно центра и края, затем уточняет три перспективных положения шагом 1/32 периода. Отбрасывает доминируемые варианты по числу предупреждений, минимальной ширине, количеству подрезок, количеству исходных плиток и асимметрии. Показывает до четырёх пространственно различных компромиссов; их может быть меньше, если остальные эквивалентны или хуже. Это эвристика, не доказательство глобального оптимума.

Ширина детали — меньшая сторона минимального повёрнутого охватывающего прямоугольника. Маленькая площадь — меньше квадрата заданного порога. Острый угол — меньше 30°. Вогнутые формы, отверстия и детали с более чем четырьмя вершинами отмечаются для проверки. Этот набор не обнаруживает все узкие перешейки; сложный раскрой нужно проверять вручную. Симметрия оценивается только для прямоугольной области вдоль осей плитки, как средняя абсолютная разница крайних подрезок по X и Y.

Одна исходная плитка на занятую ячейку сетки; отдельные фрагменты той же ячейки считаются из одной плитки. Повторного использования обрезков между ячейками, оптимизации раскроя, учёта толщины реза, рисунка и запаса на бой нет. Отходы = площадь исходных плиток минус фактическая площадь деталей. Швы и отступы не включены в площадь покрытия. SVG показывает габариты, а не производственную карту резов.

До 100 точек на кольцо, 20 отверстий, ±100 м координаты, до 1600 ячеек охватывающей сетки. Раскладка сохраняется по кнопке «Сохранить» и при возврате кнопкой «Все проекты». Названия, адреса и планы хранятся в localStorage этого браузера. JSON-экспорт содержит геометрию раскладки, без названия и адреса. Сервер пока не сохраняет проекты в базу и не имеет авторизации.
